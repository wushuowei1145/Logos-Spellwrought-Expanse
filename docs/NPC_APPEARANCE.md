# NPC 随机外观方案

适用于在世界结构里大量生成的普通 NPC（类似村民）。同一种族的 NPC 也要长得不一样，避免玩家视觉疲劳；同时数量多，必须控制性能。

本文是设计方案，**尚未实现**。模型规范见 [NPC 模型美术规范](NPC_MODELS.md)，动画见 [NPC 动画制作规范](NPC_ANIMATIONS.md)，好看的做法见 [NPC 模型制作指南](NPC_MODELING_GUIDE.md)。幼年、成长、伴侣与繁殖见 [NPC 人口与繁殖](NPC_POPULATION.md)，第一个种族的规划见 [森林精灵](NPC_RACE_FOREST_ELF.md)。

## 1. 总体思路：零件库 + 配色库，不做整人预设

不做「一个预设就是一整个人」。美术只准备有限的**零件**（发型、五官、服装）和手调的**色阶**，生成时按种族、阵营、职业的规则抽取组合。

组合数是相乘的。例如 8 套发型 × 10 种发色 × 6 种眼型 × 8 种瞳色 × 5 种肤色 × 6 套服装 × 4 套服装配色 × 3 种体型，约 1100 万种，而美术量只是几十个零件和几十条色阶。

- **种族**决定骨架、可用零件和色阶的范围；
- **阵营 / 职业**决定服装款式和服装配色方案；
- **随机**只在这些范围里按权重抽取。

## 2. 参数与实现方式

| 参数 | 实现 | 改不改几何 |
|---|---|---|
| 性别（外观） | 选择成年身体和对应的零件池；幼年不体现（第 3.1 节） | 是，换身体 |
| 年龄 | 幼年 / 成年用原版年龄，换独立的幼年身体；成年再分青年、成年、长者三个外观段 | 幼年换身体 |
| 发型 | 同一模型里多套发型骨骼组，只显示选中的一套 | 是，靠显示 / 隐藏 |
| 发色、瞳色、肤色、服装颜色 | 调色板替换（第 4 节） | 否 |
| 五官（眼、眉、嘴） | 在贴图上换图块，画进已分配好的脸部与眼睛 UV 区 | 否 |
| 服装 | 服装骨骼组显示 / 隐藏，款式由职业或阵营决定，配色随机 | 是，靠显示 / 隐藏 |
| 身高 | 原版 `Attributes.SCALE` 整体缩放，约 ±8% | 否 |
| 身材 | 几种体型，按骨骼小幅缩放（腿长、肩宽、胸腰宽），±10% 以内 | 否 |

- **共用骨架**：一个种族一套骨架和骨骼名，所有变体共用同一份动画文件，`NpcAnimations` 直接可用。
- **身高用整体缩放**：原版 `SCALE` 属性同时处理碰撞箱、眼高和渲染缩放，而且整体缩放不会让像素变形。接入时要确认 GeckoLib 渲染器是否应用了实体缩放，没有就在 `NpcRenderer` 里乘上（在固定的 0.5 之外）。
- **身材只做小幅缩放**：单方向缩放会把像素拉扁，幅度大了能看出贴图颗粒粗细不一。差别大的体型（如结实型）单独做一套躯干骨骼组。

## 3. 模型约定

- 每个种族的每种身体一个模型文件（`geckolib/models/entity/<种族>_<female|male|child>.geo.json`，第 3.1 节），包含这种身体能用的所有发型和服装零件。渲染器按原版年龄切换成年 / 幼年模型，和 26.1 原版的成年 / 幼年模型对（`AdultAndBabyModelPair`）同一思路。
- 头部零件（发型、头饰、兽耳）在共用的头部零件文件里制作，由脚本复制进各身体模型，改一处即可。
- 骨骼组命名：
  - 发型：`Head` 下的 `hair_<id>`，例如 `hair_twintail`、`hair_bob`；
  - 服装：挂在对应身体骨骼下的 `outfit_<id>_<部位>`，例如 `outfit_robe_body`、`outfit_robe_leftarm`；
  - 同一零件分布在多根身体骨骼上时，共用同一个 `<id>`，显示 / 隐藏一起切换。
- 头发、裙摆需要摆动的部分照常拆成独立骨骼，名字带上零件 ID（`hair_twintail_l1`），动画按骨骼名生效，缺失的骨骼会被忽略。
- 零件之间的冲突写进零件清单：例如某发型会穿过兜帽、某服装要隐藏尾巴。冲突的组合在生成时直接排除，不靠模型硬塞。
- 身体本身（脸、手、腿）每种身体只做一份，零件盖在外面。被完全盖住的身体面可以按服装隐藏，减少方块数。

### 3.1 身体：成年两性 + 中性幼年

- 每个种族最多三种身体：成年女性、成年男性、幼年。可以先只做其中一部分，例如第一批只做成年女性和幼年。
- **幼年身体偏中性，外观看不出性别**，约 2.5–3 头身。性别在出生时就已决定，只是到成年才体现在外观上；它是内部数据，不向玩家展示（人口文档第 2 节）。
- 幼年有自己的发型池和服装（中性款），不和成年共用。
- 种族特征（精灵耳、猫耳与猫尾、狐耳与狐尾）三种身体都有，挂点位置相同。

### 3.2 头部标准化

日漫风格里，不同年龄的头差不多一样大，差别主要在身体长短。所以：

- **同一种族的三种身体，头部尺寸、`Head` 骨骼位置以上的结构和脸部 UV 布局完全一致。**
- 五官图块、兽耳、头饰在所有身体上共用；发型按年龄段分池，但几何可以互相借用。
- 骨骼名三种身体都相同，动画通用（幼年可以另做步幅更小的 `walk`，不做就共用）。

这条要在画第一个种族的身体之前就定下来，否则以后补男性或幼年时，头部零件要全部重做。

## 4. 贴图：调色板替换

### 4.1 标记色

- 美术用**标记色**绘制会变色的区域。每个颜色通道预留一组固定的 RGB 值，一个通道约 5 级明暗：
  - 头发、肤色、瞳色；
  - 服装主色、辅色、点缀色。
- 标记色表放在数据文件里（例如 `npc_palettes/markers.json`），选色时避开普通颜色，以免误替换。
- 不变色的部分（金属扣、白色眼白、描边）直接画成最终颜色，合成时不动。

### 4.2 色阶

- 每个通道有若干条**手调色阶**，例如 `npc_palettes/hair/ash_blonde.json`，每条 5 个颜色，和标记色一一对应。
- 色阶由美术调色，亮部偏暖、暗部偏冷的色相变化保留在色阶里。
- **不要**用随机 RGB 或 HSV，那样容易配出难看的颜色；也**不要**用顶点染色（贴图乘一个颜色），暗部会发灰发脏。

### 4.3 五官图块

- 眼睛平面已有单独的较高像素区域（规范第 4 节）。不同眼型画成同样大小的图块，合成时替换进眼睛的 UV 区。
- 眉、嘴同理，替换脸部正面对应的区域。
- 以后的表情（眨眼、笑）也走同一套：表情图块按同样规则替换。

### 4.4 合成与缓存

- 客户端第一次遇到某种外观时，把底图、五官图块、服装层按选中的色阶合成一张贴图，注册为动态贴图。
- 以外观组合为键缓存，外观相同的 NPC 共用一张；没人使用时按最久未使用淘汰并释放。
- 贴图很小（例如 96×80 约 30 KB），合成只做一次，没有每帧开销。
- 源图（底图、图块）读取一次后保存在内存里，不要每次合成都重新读资源。

## 5. 生成规则

- **按权重抽取**，不均匀随机。常见的发色、体型权重高，稀有的低。
- **关联**：允许设置参数之间的关联权重，例如某种族金发多配蓝眼或金眼、年长者多用某些发型。
- **服装配色从方案里选**：每个阵营 / 职业有几套配色方案，一套是 2–3 个已经调好、互相协调的颜色，不分别随机。
- **排除冲突**：零件冲突（第 3 节）和难看的颜色组合在规则里排除。
- 规则写成数据文件，按种族组织，美术和策划可以直接调权重，不用改代码。

### 5.1 已实现的单向零件依赖

零件表 `data/logos_dimension/npc_races/forest_elf.json` 支持 `requires`。例如：

```json
"requires": {
  "hair_hooded": {"outfit": "outfit_ranger"}
}
```

意思是选中兜帽发型后，服装槽必须使用守林人披风；披风本身仍能搭配任何其他不冲突的发型。出生随机与外观校正都执行这条规则，因此旧记录或手动指定的孤立兜帽会补为披风服装，原有兜帽与枝冠互斥规则继续生效。

依赖方向必须从前面的槽位指向后面的槽位（当前发型在服装之前），目标必须是该槽位的有效零件。制作库的规则源在仓库外 `forest-elf-model/forest_elf/race.json`，合并脚本将其写入 `build/parts.json`；以后改规则时同步游戏零件表，不需要编辑 `.bbmodel` 形体。

## 6. 数据存储

- NPC 生成时只抽一次，存**解析后的外观记录**，不存随机种子：
  - 种族、性别、成年外观段（青年 / 成年 / 长者）；
  - 各通道的色阶 ID、五官图块 ID、耳尾型（终身不变）；
  - **幼年零件组**：幼年发型、幼年服装；
  - **成年零件组**：成年发型、头饰、服装、体型；第一次长大时才生成，之前为空；
  - 身高系数。
- 两组零件分开存：成年 NPC 被衰退符文变回幼年时显示幼年零件组（没有就当场生成），再长大时**恢复原来的成年零件组**，不重新抽，长回来还是原来的样子。
- 幼年与成年由原版年龄决定（见 [NPC 人口与繁殖](NPC_POPULATION.md)），外观记录里不重复存。
- 记录用 Codec 存档、用 StreamCodec 同步给客户端，几十字节。
- **为什么不存种子**：以后新增发型或色阶时，同一个种子会抽出不同的结果，已有的 NPC 会集体变脸。
- 记录里的 ID 用字符串（如 `logos_dimension:hair/twintail`），不用序号，增删内容时不会错位。ID 找不到（零件被删除）时，回退到该种族这一项的默认值。

## 7. 性能

真正的开销有两处：GeckoLib 每帧逐个方块提交顶点（没有显存缓存），以及服务器端的 AI 和寻路。

### 7.1 渲染

- **方块预算**：普通 NPC 同时显示的方块数（身体 + 一套发型 + 一套服装）不超过约 250–300 个。车万女仆常见的上千方块模型不适合批量生成。隐藏的骨骼组不提交顶点，但会参与动画计算，所以主模型里的零件总数也不要无限增加。
- **距离降级（LOD）**，距离以视距为准、可调：
  - 约 24 格外：关闭头发、裙摆的次级动画和物理；
  - 约 48 格外：隐藏细节骨骼（瞳孔高光、裙褶分片、发梢、小饰品），或换成低模；
  - 更远：降低动画更新频率。
- 贴图合成后缓存（第 4.4 节），不产生每帧开销。

### 7.2 服务器

- 用简单的目标（Goal）组合，不用村民那套 Brain。
- 附近没有玩家时降低 AI 更新频率。
- 结构里的生成密度要克制，必要时让远处的 NPC 休眠。

## 8. 重要 NPC

- 艾洛蒂这类重要 NPC 使用手工制作的独立模型和贴图，不走随机外观，也不受普通 NPC 的方块预算限制。
- 需要「同一种族、但固定长相」的半重要 NPC，可以写死一份外观记录，复用随机外观的零件和色阶。

## 9. 美术交付

每个种族交付：

- 主模型：本批要做的身体（成年女性 / 成年男性 / 幼年，头部按第 3.2 节统一）+ 全部发型、服装骨骼组，命名按第 3 节；
- 底图：会变色的区域用标记色画；
- 五官图块：每种眼型、眉形、嘴形一张，尺寸与对应 UV 区一致；
- 色阶：每个通道若干条；
- 零件清单：每个零件的 ID、方块数、冲突关系、适用的职业 / 阵营；
- 生成规则：权重、关联、服装配色方案。

验证：每个零件单独显示时方块数在预算内；任意抽 20 个组合截图检查，没有穿模、没有难看的配色。

## 10. 推进顺序

1. 定下标记色表、骨骼组命名和方块预算（本文第 3、4、7 节），美术据此开始绘制。
2. 做最小原型：2 套发型、2 种眼型、3 条色阶，验证合成、缓存、骨骼组切换、外观记录的存档与同步。
3. 原型通过后，美术批量扩充零件库，策划填写生成规则。
4. 加入距离降级，在结构里大量生成，实测帧率与服务器开销。

待确认：GeckoLib 渲染器是否应用实体缩放；隐藏骨骼组的动画计算开销；动态贴图在 26.1 的注册与释放方式。
