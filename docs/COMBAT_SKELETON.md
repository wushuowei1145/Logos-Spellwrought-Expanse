# 战斗骨架与兼容性规范

玩家和附属的人形生物共用一套连招数据：动作按车万女仆（TLM）GeckoLib 骨架的骨骼名制作，玩家在战斗时套用同名的参考骨架，NPC 直接用自己的 TLM 模型。本页规定骨骼标准、文件格式和运行时；**第 1 节的兼容性规则优先于本页其他内容和任何新功能**。

参考过 Epic Fight 与拔刀剑 Resharped 的动作系统，只借鉴思路，不使用它们的代码或资产（Epic Fight 资产为保留所有权利）。

## 1. 兼容性规则

Epic Fight 的手感来自全身动作，兼容性问题则来自它接管得太多：替换所有生物的渲染器、给所有物品和生物套用战斗能力、改原版的伤害、硬直和体力、默认改镜头。本附属反过来做，每条规则都写明现状。

| # | 规则 | 现状 |
|---|---|---|
| 1 | **只接管自己的东西。** 只对本附属注册的武器和本附属的生物生效；不改原版生物、其他模组的物品与实体，不给它们加战斗能力。 | 长剑满足：只在主手是本附属长剑时拦截攻击与使用键。 |
| 2 | **伤害走原版流程。** 命中统一调用 `player.attack` / 原版伤害源，附魔、属性、冷却、其他模组的伤害事件照常生效；不新增全局的体力、硬直、格挡规则。 | 长剑满足：`LongswordCombat` 只决定出招时机，结算交给 `player.attack`。 |
| 3 | **只在动作进行时接管，平时完全原版。** 拔剑到收剑之间才替换双臂；收剑、切物品、死亡、离线后立即恢复原版。不替换玩家或生物的渲染器，用 NeoForge 的渲染层和渲染状态数据挂接。 | 长剑满足。 |
| 4 | **最少 Mixin，只追加不覆盖。** 不用 `@Overwrite`，不取消原版渲染方法；新增功能先找事件和渲染层。现有唯一相关注入是 `HumanoidModel.setupAnim` 末尾，只在本附属的渲染数据存在时改躯干并隐藏双臂。 | 满足；新增注入要在 PR 里说明为什么事件做不到。 |
| 5 | **失败即退回原版。** 骨架、武器网格、动作文件缺失或损坏，骨骼不全，动作名不存在时：记一次日志，退回原版持物与挥手，不崩溃、不卡在动作状态。Molang 表达式不求值，按 0 处理并警告。 | `LongswordRig` 与 `CombatClip` 已实现。 |
| 6 | **缺骨容忍。** 动作里有、模型里没有的骨骼直接忽略；模型里有、动作里没有的骨骼保持静止姿势或交给原有动画。第三方 TLM 模型不需要添加本页的扩展骨骼。 | `CombatPose` / `CombatSkeleton` 已实现；NPC 接入时沿用。 |
| 7 | **不抢输入、不改镜头。** 只在手持本附属战斗武器时拦截攻击键和使用键；不强制第三人称、不锁视角、不改 FOV。以后加镜头震动之类的反馈，默认轻微，并提供客户端开关。 | 满足；镜头反馈未做。 |
| 8 | **网络可选、服务端权威。** 只给协商了本附属通道的连接发动作包；服务端决定出招和命中，客户端只做表现。 | 满足（`NetworkRegistry.hasChannel`）。 |
| 9 | **数据驱动、命名空间隔离。** 骨架、武器网格和动作都放在 `assets/logos_dimension/combat/`；资源包可以整体替换，本附属不写入其他命名空间，也不要求其他模组注册任何东西。 | 满足。 |
| 10 | **与其他玩家模型模组共存。** YSM、Figura 等替换了玩家外观时，不在它们的模型上再叠一双手臂，退回“只画剑、不替换手臂”。 | **未实现**，接入 NPC 前要做。 |

新功能做不到这些规则时，先改设计；确实要例外，在 PR 说明里写明影响范围和关闭方法。

## 2. 骨骼标准

骨骼名就是 [NPC 模型美术规范](NPC_MODELS.md) 第 2 节的 TLM 必需层级（`Root`、`AllBody`、`UpBody`、`UpperBody`、`AllHead`、`Head`、`Arm`、左右 `Arm` / `ForeArm` / `Hand`、`DownBody`、左右 `Leg` / `LowerLeg` / `Foot`），左右指角色自身的左右。代码里的常量见 `dev.logos.dimension.combat.CombatBones`。

在此基础上加两根扩展骨骼，只存在于战斗动作和参考骨架里：

| 骨骼 | 父骨骼 | 用途 |
|---|---|---|
| `Weapon` | `UpBody` | 武器握柄原点。武器由动作直接驱动，双手跟随剑柄，所以能做拔剑、收剑和换手。 |
| `Sheath` | `UpBody` | 剑鞘或其他挂在身上的收纳物。 |

NPC 模型**不需要**添加这两根骨骼：运行时自己算出它们的位置并绘制武器网格。

各骨骼在战斗动作里的含义：

- `UpBody`：腰部，上半身相对下半身的扭转与俯仰。玩家第三人称把它映射到原版躯干。
- `Head`：动作里可以有，但玩家的头保持原版的看向，只跟随躯干带来的颈部位移。
- `Root`：整体位移；第一人称用它把整套手臂和剑放到画面右侧。
- 腿部骨骼：标准里保留；当前长剑动作没有腿部轨道，玩家的腿由原版绘制。

## 3. 坐标、零位与插值

- **动作文件就是 Blockbench 导出的 Bedrock 动画**（`format_version` 1.8.0），可以在 Blockbench 里直接做、直接导出。文件中的符号与 Blockbench 的 Bedrock 导出一致；运行时读入后旋转 X、Y 取反、位移 X 取反，换回 Blockbench 空间（Y 向上、正面 -Z、角色右侧 +X、像素单位、ZYX 欧拉角）。这条换算已用美术包里的 `.bbmodel` 与它导出的 `.animation.json` 对照确认。
- **标准零位**：双臂、双腿竖直下垂，面朝 -Z，所有旋转都是相对这个零位的局部旋转。玩家参考骨架没有静止旋转，所以动作值就是最终角度。
  - TLM 模型可能自带静止旋转（例如森林精灵的上臂向外张约 18°，是精灵自己的造型，不是 TLM 标准）。套到 NPC 时要先扣除这部分，否则手臂会多张开。在 Blockbench 里把战斗动作放到这类模型上预览，看到的手臂会多出这个角度，正式效果以玩家参考骨架为准。
- **尺寸**：位移按参考骨架（原版玩家比例，脚底到肩约 23 像素）制作。体型不同的骨架按胯高缩放位移，双手握柄用 IK 修正（NPC 接入时实现）。
- **插值**：支持 `linear`、`catmullrom`、`step` 和 `pre` / `post` 分段值；关键帧也可以直接写成数组（线性）。
- **命名**：同一类武器、同一视角的动作放一个文件，例如 `longsword_tp.animation.json`，文件里用短名（`draw`、`idle`、`attack_1`…），不加 `animation.<asset>.` 前缀。这是 Logos 动画命名规则的例外，理由与 NPC 动画相同：短名才能跨模型复用。

## 4. 文件

| 路径（`assets/logos_dimension/combat/` 下） | 内容 |
|---|---|
| `skeletons/player_tp.json`、`player_fp.json` | 玩家参考骨架：`bones`（名称、父级、枢轴，Blockbench 空间）、`weapon_scale`（该视角的武器缩放）、`skin`（按原版皮肤取 UV 的手臂分段）。第一人称的手臂枢轴与第三人称不同，所以分两份。 |
| `weapons/<武器>.json` | 武器网格：`texture`、`texture_size`、`cubes`（`part` 为 `weapon` 或 `sheath`）。坐标相对握柄原点、按原始美术尺寸（缩放 1），等于物品模型像素坐标减去 (8, 1, 8)。 |
| `animations/<类别>_<视角>.animation.json` | Bedrock 动作。 |

两把长剑的数据由 `tools/import_longswords.py` 从仓库外的审定美术工程生成：曦誓工程提供玩家骨架和动作，两把剑各自提供网格。手改美术工程后重跑脚本，不要手改生成的 JSON。

招式（第 5 节）放在服务端数据包：`data/<命名空间>/combat/movesets/<名>.json`，长剑是 `data/logos_dimension/combat/movesets/longsword.json`。独立服务端不加载 `assets`，所以招式不和动作放在一起；客户端也不需要招式文件。

## 5. 招式状态机

招式文件描述一张状态图：每个**招式**对应一段动作，**转移**说明在什么输入、什么时间窗口切到哪一招。服务端逐刻推进并决定出招与接触时刻；客户端只收到“动作名、开始刻、播放速度、播放方式”，自己取样画面，不做任何决定。玩家用按键、NPC 用 AI 向同一台状态机（`MoveRunner`）发送输入。

```json
{
  "start": "draw", "sheathe": "sheathe", "combo_memory": 1.5,
  "moves": {
    "idle": {"clip": "idle", "length": 2.4, "playback": "loop",
             "on": [{"input": "attack", "to": "attack_1", "combo": true}, {"input": "use_press", "to": "charge_start"}]},
    "attack_1": {"clip": "attack_1", "length": 0.625, "attack_speed_base": 1.6, "contact": 0.24,
                 "combo_next": "attack_2", "next": "idle",
                 "on": [{"input": "attack", "to": "attack_2", "window": [0.425, 0.625], "queue": true}]},
    "charge_cancel": {"clip": "charge_start", "playback": "reverse", "next": "idle"},
    "sheathe": {"clip": "sheathe", "length": 1.2, "next": "$clear"}
  }
}
```

| 字段 | 含义 |
|---|---|
| `start` | 拿起武器时进入的招式。 |
| `sheathe` | 换下武器时强制进入的招式；播完（`next` 为 `$clear`）后交回原版。不写时换下武器立即结束。 |
| `combo_memory` | 连招记忆（秒，按游戏时间）：从上一段连招开始算，在这段时间内从待机出招会接着上一段的 `combo_next`。 |
| `clip` | 动作名，对应 `animations/<类别>_<视角>.animation.json` 里的短名；不写时与招式同名。 |
| `length` | 动作时长（秒），必须与动作文件一致（`MovesetTest` 检查）。 |
| `playback` | `once`（播完停在末帧，默认）、`loop`（循环，不会自动结束）、`reverse`（从进入时上一招式已播到的位置倒放回 0，用于中途取消）。 |
| `attack_speed_base` | 写了就按攻速缩放：播放速度 = 实际攻速 ÷ 该值（限制在 0.2–4 倍），进入招式时确定。 |
| `contact` | 接触时刻（动作时间，秒）；到点时由武器或生物结算一次命中。 |
| `next` | 播完后的去向；`$clear` 表示结束整套招式。不循环的招式必须写。 |
| `combo_next` | 连招的下一段，配合 `combo_memory` 与转移的 `combo`。 |
| `reset_combo` | 进入时清空连招记忆（例如蓄力）。 |
| `on` | 转移列表，按顺序取第一条满足条件的。 |

转移字段：`input` 为 `attack`、`use_press`、`use_release`；`to` 为目标招式或 `$clear`；`window` 为 `[起, 止]` 动作时间窗口（含端点，`止` 可省略表示到结束）；`queue` 为真时输入先记下，到本招式结束的那一刻切换（不对齐游戏刻，连段节奏不漂移）；`combo` 为真时若连招记忆有效，改去记忆中那一段的 `combo_next`。

时间约定：招式里的时间都是**动作时间**，带 `attack_speed_base` 的招式按攻速缩放；`combo_memory` 用游戏时间。播完后没有排队输入时，在到点的那一刻进入 `next`。

兼容（第 1 节第 5 条）：招式文件缺失或格式错误时 `Movesets` 记一次日志，长剑不进入持剑动作，按原版物品处理（左键是原版攻击）；客户端在服务端回报持剑动作之前也不拦截左键。

## 6. 运行时

`dev.logos.dimension.combat` 不依赖客户端类，服务端也能用（以后用于烘焙命中轨迹）：

- `CombatSkeleton`：读取骨架，按父级排序；父级缺失的骨骼当根骨骼处理，循环父级报错；`missingRequired()` 列出缺少的标准骨骼。
- `CombatClip`：读取 Bedrock 动作文件，按骨骼和通道采样。一段动作解析失败只跳过这一段。
- `CombatPose`：一帧姿势。`sample` 从动作取样，`blend` 在两帧之间过渡（位移线性、旋转四元数球面插值），`matrices` 套到任意骨架上求模型空间矩阵。
- `Moveset`：读取并校验招式文件（去向不存在、不循环却没有 `next` 等都报出原因）；`playbackSeconds` 是客户端与服务端共用的取样时间换算。
- `MoveRunner`：一名角色身上的招式状态机，只依赖游戏刻和攻速，通过 `Actor` 回调换招与接触。
- `Movesets`：按服务端资源管理器缓存招式，`/reload` 后重新读取。

长剑客户端 `LongswordRig` 用它们取样并绘制剑、剑鞘和分段手臂。迁移到本标准时，用迁移前的渲染算法对旧数据求了参考矩阵（`src/test/resources/combat/longsword_reference.json`），`LongswordMotionTest` 逐矩阵对照，保证动作外观没有变化。长剑招式迁移到状态机时，`MovesetTest` 按迁移前的时间轴逐刻对照出招、接触、排队接段、连招记忆、蓄力与取消。

迁移后唯一的时序差别：旧版下一段的输入窗口固定为收势最后 4 游戏刻，现在是动作时间 0.425 秒起；原版剑攻速（1.6）下两者相同，攻速被其他效果改变时窗口随动作一起缩放。

## 7. 后续顺序

1. 改手感：取消窗口、整段输入缓冲、出招间用 `blend` 过渡；先决定提前接刀时伤害节奏怎么平衡。冲刺、空中等输入条件按需要加入。
2. 玩家全身参考骨架：腰与腿分段、分段护腿与靴子，仍然只在动作期间替换。
3. 第 1 节第 10 条：检测其他玩家模型模组并退回。
4. NPC 适配：在 `NpcRenderer.adjustModelBonesForRender` 里把姿势写进 GeckoLib 骨骼，扣除静止旋转、按胯高缩放、双手握柄 IK；战斗层只覆盖它接管的骨骼，腿可以继续用 GeckoLib 的行走动画。核对 GeckoLib 读取 Bedrock 旋转的符号与本页一致。
5. 命中轨迹：离线烘焙每段动作的剑根、剑尖轨迹，服务端按体型缩放后做扫掠判定，玩家与 NPC 共用。
