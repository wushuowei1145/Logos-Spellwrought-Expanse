# 魔女之森乐器

> 状态：维护者 2026-11-10 确认方案，第一版已实现（第 11 节是实现说明）。声音只能人工试听，见第 11.4 节哪些还没验证。

给附属加一批魔女之森（Hexenwald）风格的乐器：玩家可以在演奏界面用键盘实时弹奏；可以用「打孔纸带」自动演奏，纸带能录制、能编写；也能读取玩家自己的 MIDI 文件来播放。

## 1. 外观方向

魔女之森是人类领导、多族共存的君主立宪国家，文化中心是星辰花之都：大理石、木结构、魔法师塔、教堂、温室。乐器要像这个国家的学院和教堂里会摆的东西：**优雅、古典、带一点魔法**，不走华丽浮夸的路线。

共同元素：

- **材质**：白色大理石纹的漆面（或乳白漆）配深色胡桃木；黄铜或淡金色的收边、铰链、踏板。
- **星辰花**：五瓣小星花作为镶嵌纹样，少量点缀（琴盖内侧、竖琴共鸣箱、纸带的封条），不铺满。
- **灵猫**：灵猫在这个国家地位很高，所以竖琴的柱头雕成一只坐着的猫（耳朵、尾巴绕柱），钢琴的谱架两端有小小的猫耳卷饰。
- **魔法**：演奏时从琴身飘出原版音符粒子（复用原版 `note` 粒子，按音高着色，不新画贴图）；纸带自动演奏时，纸带上被读到的孔会有很淡的光。不加额外的光柱、法阵。
- 模型与贴图按惯例由 Python 代码生成，不用图像生成服务。2026-11-14 起全部乐器按 [INSTRUMENT_ART.md](INSTRUMENT_ART.md) 重做：逐面手绘的贴图页（`tools/instrument_models/`），不再拉伸原版贴图。

## 3. 音源

### 3.1 为什么不能直接用音符盒

原版音符盒只有 25 个音（两个八度），是靠把**一个**采样变调实现的；声音引擎把变调倍率限制在 0.5–2.0 之间，再宽就会失真、截断。钢琴要 88 个音，竖琴 47 个，单采样做不到，也不好听（变调一个八度以上音色会明显发尖或发闷）。

### 3.2 多采样 + 小幅变调

- 每种乐器每隔**小三度（3 个半音）**录一个采样，演奏某个音时取最近的采样，变调不超过 ±1.5 个半音（倍率约 0.917–1.091），听不出变色。
- 钢琴：A0–C8 共 30 个采样；第一版一个力度层，力度只改音量。第二版再考虑 2 个力度层（轻弹的音色更暗）。
- 竖琴：C1–G7（MIDI 24–103）共 27 个采样（真竖琴只有 47 根全音阶弦，但本作半音都能弹，见 4.2）。
- 采样格式：单声道 OGG，44.1 kHz；钢琴每个约 4–6 秒（自然衰减），竖琴约 3–4 秒。估计钢琴 ~2.5 MB、竖琴 ~1.2 MB。
- 注册方式：`sounds.json` 里每个采样一个声音事件，例如 `instrument.grand_piano.s21`（`s` 后面是采样的 MIDI 音高）；用 `SoundEvent.createFixedRangeEvent` 固定可闻距离（钢琴 32 格、竖琴 24 格）。声音分类用原版「唱片机/音符盒」（`RECORDS`），玩家可以用原版音量滑块调整。

### 3.3 采样从哪来

> **2026-11-11 起改用录音采样**（维护者试玩后决定，见第 15 节和 [乐器采样](INSTRUMENT_SAMPLES.md)）：钢琴用 Salamander Grand Piano，
> 其余乐器用 VCSL、VSCO 2 CE；两个库都没有的钢片琴仍合成，管风琴仍按音栓现场合成。下面是最初的讨论。

这是第一个需要维护者决定的地方：

- **方案 A：全部用代码合成**（和美术「代码绘制」的规矩一致）。竖琴用 Karplus-Strong 拨弦 + 共鸣箱滤波，效果很好；管风琴用加法合成（多个音栓叠加），效果也很好；**钢琴**用模态合成（弦的非谐性、双段衰减、琴槌噪声）能做出「像钢琴」的声音，但和真钢琴采样比会有电子味。脚本放 `tools/instrument_samples.py`，可重复生成。
- **方案 B：钢琴用开放许可的采样库**，竖琴和管风琴仍然合成。候选：Salamander Grand Piano（CC-BY 3.0，需在 CREDITS.md 署名）、University of Iowa MIS 钢琴（官方声明可自由使用）。下采样后只取 30 个音，按 CREDITS.md 登记来源和许可。
- **已定（2026-11-10）：先按方案 A 全部用代码合成**。钢琴试听不满意再换方案 B，两者对代码没有影响（只换 OGG 文件）。

### 3.4 播放一个音

- 客户端为每个音生成一个可更新的声音实例（`TickableSoundInstance`）：按下时播放，松开时在 ~100 ms 内把音量降到 0 再停止（直接停会有爆音）。钢琴踩下延音踏板时松键不停音。
- 力度（1–127）映射到音量，曲线 `(v/127)^1.6`。（换成录音采样后：力度先选力度层，再按采样表的曲线定音量，见第 15 节。）
- **复音上限**：每台乐器最多 32 个同时发声的音，全局最多 96 个；超出时先停掉「已松开、最旧」的音。原版普通声道池约 247 个，要给游戏的其他声音留余量。上限写进客户端配置。

## 4. 实时演奏

### 4.1 演奏界面

右键钢琴或竖琴打开演奏界面（坐下 / 站着演奏的姿势放第二版）。界面上半部分是可点击的屏幕键盘（按下的键会亮），下半部分显示当前八度、力度、延音状态。背景沿用 Logos 法术编辑器的羊皮纸九宫格（`logos:textures/gui/spell_editor_parchment.png`），不另画。

界面打开时，键盘输入只给乐器，不触发游戏按键；`Esc` 关闭。

### 4.2 键位映射（默认，可在客户端配置里改）

两排「钢琴式」布局，共 29 个键，覆盖约两个半八度：

```
 上排（高八度）   2 3   5 6 7   9 0        黑键
                Q W E R T Y U I O P       白键  → C D E F G A B C D E
 下排（低八度）   S D   G H J              黑键
                Z X C V B N M             白键  → C D E F G A B
```

| 键 | 作用 |
|---|---|
| `Z`–`M` / `Q`–`P` 及其间的数字、字母 | 弹奏（按下发音，松开止音） |
| `←` `→` | 整体降 / 升一个八度 |
| `↑` `↓` | 力度 +16 / −16（默认 96） |
| `空格` | 延音踏板（按住） |
| 鼠标 | 点屏幕键盘也能弹 |

- 竖琴额外有「全音阶模式」（第一版就做）：三排字母键全部映射为白键（`Z`–`/`、`A`–`'`、`Q`–`P`），一次覆盖四个八度，适合刮奏；数字键 `1`–`7` 像竖琴的踏板一样给 C–B 各自升半音。
- 按住不放时系统的「键盘连发」会被忽略，不会重复触发。

### 4.3 MIDI 键盘（第二版）

客户端可以接实体 MIDI 键盘（`javax.sound.midi` 的输入设备），直接当演奏输入。已做，见第 12 节。

## 5. 多人同步

两种情况分开处理：**实时演奏**传音符，**纸带播放**只传「从哪一刻开始放哪卷纸带」。

### 5.1 实时演奏

1. 演奏者的客户端**立刻**在本地发声（演奏者自己听不到延迟）。
2. 客户端把这一 tick 内的按键攒成一批，每个音带上「相对本批开始的毫秒偏移」，发给服务端（`InstrumentNotesPayload`：方块位置、序号、若干条 {偏移, 音高, 力度, 按下/松开}）。
3. 服务端检查：玩家在乐器 6 格内、乐器当前确实由这个玩家演奏（同一台乐器同时只能一个人弹）、速率不超过平均每秒 128 个事件（瞬间最多 64 个），超出直接丢弃。
4. 服务端把这一批转发给附近（钢琴 48 格内）正在追踪这个区块的其他玩家，不发回演奏者。
5. 听众客户端收到后**统一延后约 100 ms** 再按批内偏移排期播放：网络抖动被缓冲吸收，节奏和演奏者完全一致；代价是听众比演奏者晚约 0.1 秒，听众察觉不到。
6. 演奏者离开、断线或关掉界面时，服务端广播「全部松开」，避免别人那里卡音。

### 5.2 纸带播放

- 服务端只记录播放状态：纸带 ID、开始时的服务器 tick、开始位置、播放哪些声部、是否暂停。
- 开始 / 暂停 / 停止时，向追踪该区块的玩家广播一次 `RollPlaybackPayload`。客户端按纸带 ID 取数据（本地有缓存就不再取，见 6.3），然后**在客户端本地按时钟逐个播放音符**，服务端不逐音发包，带宽很小。
- 时钟：客户端以收到开始包的时刻为锚，用本地真实时间推进（服务端卡顿不会让音乐变慢）；服务端每 5 秒发一次位置心跳，偏差超过 150 ms 才修正，避免频繁跳音。
- 后来的人走进范围、或重新加载区块时，服务端补发当前状态，客户端从当前位置开始放（只放还没结束的音）。
- **合奏**：同一红石信号在同一 tick 启动的多台乐器，开始包是同一 tick 发出的，在每个客户端上天然对齐。一卷纸带可以有多个声部（来自 MIDI 的不同通道），每台乐器在纸带页里选自己演奏哪些声部，于是一卷纸带能分给钢琴和竖琴一起合奏。
- 红石：乐器收到红石上升沿开始播放，失去信号不停（和唱片机一样，可以在纸带页切换为「信号停止时停止」）。

## 6. 纸带

### 6.1 存储方式

纸带内容可能很大（一首 MIDI 几千个音），不能直接塞进物品数据：箱子里放一堆纸带会让区块和背包同步包过大。所以照原版地图的做法：

- **物品只存引用**：数据组件 `logos_dimension:music_roll` = { 纸带 ID（UUID）、曲名（≤ 64 字符）、作者、时长、音符数、声部名列表、内容哈希（8 字节）}。
- **内容存服务端**：存档目录 `data/logos_dimension/rolls/<UUID>.lroll`，用到时才读入，内存里保留最近使用的 64 卷。
- **内容不可修改**：纸带写好就不变；编辑一卷纸带会生成新 ID（复制出的纸带仍指向旧内容，互不影响）。因为不可变，客户端可以放心按 ID + 哈希缓存。
- 内容文件不会自动删除（和地图一样）；第二版给管理员一个清理没有物品引用的纸带的命令。

### 6.2 内容格式（`.lroll`，二进制，第 1 版）

时间一律用**毫秒**，速度变化在写入时已经折算好，播放时不用再算速度表。

```
魔数        "LRL1"（4 字节）
标题        字符串（varint 长度 + UTF-8）
作者        字符串
节拍提示    varint BPM×100、拍号分子、分母（只给编辑器画网格用，播放不读）
声部数      byte（≤ 16）
  每个声部：名字字符串、音色提示（GM 音色号，byte）
事件数      varint
事件（按开始时间排序）：
  varint  距上一个事件开始的毫秒数
  byte    类型：0 音符，1 延音踏板踩下，2 延音踏板松开
  音符时：byte 声部、byte 音高（MIDI 0–127）、byte 力度（1–127）、varint 时值毫秒
  踏板时：byte 声部
```

限制（服务端收到时逐条校验，不合格整卷拒收）：

| 项 | 上限 |
|---|---|
| 编码后大小 | 256 KiB |
| 事件数 | 50 000 |
| 总时长 | 20 分钟 |
| 单音时值 | 30 秒 |
| 声部 | 16 |
| 每个玩家每分钟上传纸带 | 4 卷 |

播放时，超出乐器音域的音按八度移进音域（钢琴 21–108，竖琴 24–103）。

### 6.3 传输

- 上传（录制、编写、导入 MIDI）：客户端把编码好的 `.lroll` 分成每块 ≤ 32 KiB 发给服务端，服务端拼好、校验、写文件、把空白纸带换成打孔纸带。
- 下载（播放时）：客户端按 ID 请求，服务端分块发送；客户端在内存里按 ID 缓存（第二版考虑磁盘缓存）。
- 服务端配置 `[instruments] allowRollUpload`（默认开），关掉后只有管理员能写纸带。

### 6.4 怎么得到一卷打孔纸带

1. **录制**：把空白纸带放进乐器，在演奏页点「● 录制」，弹完点「■ 停止录制」。录制在**演奏者客户端**完成（用本地毫秒时间戳，不受网络抖动影响），停止时整卷上传。
2. **编写**：纸带页的「打孔编辑器」（见第 7 节）。
3. **导入 MIDI**：见第 8 节。

## 7. 打孔编辑器（编写纸带）

一个钢琴卷帘式的网格：横向是时间（按节拍提示画网格，默认 1/16 音符吸附），纵向是音高；左边一列屏幕键盘可以点击试听。

- 左键空格子打一个孔（新音符），拖动改长短；右键删除；框选后可整体移动、复制。
- 顶部设置曲名、BPM、拍号、当前声部；随时可以从光标处试听（只在本地放，不上传）。
- 保存时生成新纸带（新 ID），需要乐器里放着一卷空白纸带，或者正在编辑的那卷打孔纸带（编辑后原纸带被替换为新内容）。
- 编辑器只适合几百个音以内的手写曲子；导入的大型 MIDI 也能打开查看和小改，但第一版不针对上万音符做性能优化。

## 8. 读取 MIDI 文件

### 8.1 从哪里读

- **只读演奏者自己电脑上的一个固定目录**：`<游戏目录>/logos_music/`（第一次打开纸带页时自动创建，界面上有「打开文件夹」按钮）。
- 界面只**列出**这个目录（不含子目录）下的 `.mid` / `.midi` 文件，玩家从列表里选；**不提供输入路径的地方**。
- **服务端从不读 MIDI，也不读任何玩家指定的路径**。服务端只接收客户端解析好的 `.lroll`，并按 6.2 的限制重新校验。专用服务器上的 MIDI 文件夹（让管理员预置曲库）放到第二版，同样只读固定目录。

### 8.2 安全边界

- 列出和读取前把路径规范化（`toRealPath`），必须仍在 `logos_music/` 里面；不跟随符号链接（`NOFOLLOW_LINKS`），只接受普通文件。
- 单个文件 ≤ 1 MiB，超过直接拒绝、不读入。
- 解析器自己写（标准 MIDI 文件格式 0/1），不依赖 `javax.sound.midi`：所有长度字段先和剩余字节比较再读；轨道数 ≤ 64，事件数在解析途中就按 6.2 的上限截停；遇到格式错误报出「第几轨第几个事件」，不崩溃。
- 解析在后台线程做，界面显示进度，不卡游戏主线程。

### 8.3 怎么转换

- 读取速度表（`Set Tempo`）把 tick 换成毫秒；处理运行状态、力度为 0 的音符开始（等于松开）、延音踏板（CC64）。
- 每个用到的 MIDI 通道成为一个声部，声部名取轨道名，音色提示取 Program Change；第 10 通道（打击乐）第一版忽略并在界面上提示。
- 导入预览页：列出声部（可勾选保留哪些）、时长、音符数、是否超限；确认后有两个按钮：
  - **刻成纸带**：消耗空白纸带，得到可以保存、复制、交易的打孔纸带。
  - **直接播放**：不刻纸带，作为临时纸带上传并立即播放；停止或离开后服务端删除这份临时内容。仍然受 6.2 的上传限制。

## 9. 第一版范围

**做：**

- 星辰花三角钢琴、灵猫竖琴两个方块（模型、贴图、掉落、配方、创造模式页、语言文件）。

- 演奏界面与默认键位（含竖琴全音阶模式），键位可在客户端配置里改。

## 11. 第一版实现说明

### 11.1 怎么玩

- 合成：星辰花三角钢琴 = 石英块 ×2 + 金锭 + 深色橡木板 ×2 + 音符盒 + 木棍 ×2（`QGQ / PNP / S S`）；灵猫竖琴 = 金锭 ×2 + 线 ×2 + 音符盒 + 白桦木板 ×3（` GS / GNS / PPP`）；空白纸带 = 纸 ×3 + 线（无序）。打孔纸带 + 若干空白纸带 → 同样多的复制，原纸带留在合成格里。
- 放置：钢琴占 2×2（键盘朝向放置的玩家，向右后方展开），竖琴两格高；拆任意一块整体拆掉，掉一件乐器和纸带槽里的纸带。
- 空手右键打开界面；拿着纸带（空白或打孔）右键把它放进纸带槽，槽里原来的纸带回到背包。
- 演奏页：键位见 4.2；屏幕键盘上写着每个键对应的字母，C 键标出八度；◀ ▶ 按钮也能换八度。别人正在弹时显示「某某正在演奏」，可以听不能弹。
- 纸带页：播放 / 暂停 / 停止 / 取出；多声部纸带可以逐个勾选这台乐器演奏哪些声部；红石按钮在「有信号时开始」和「信号停止时也停止」之间切换。
- 打孔编辑器（纸带页 → 打孔编辑器）：左键空格子打孔、拖动定长短；拖音符移动，拖右缘改长短；右键删除；Shift 拖空白处框选、Shift 点音符加选；Delete 删除、Ctrl+D 复制到后面、Ctrl+A 全选；滚轮翻音高、Shift+滚轮翻时间、Ctrl+滚轮缩放；空格试听。「声部」按钮轮换声部，按住 Shift 点它新增一个声部。左边的键盘点一下试听那个音。
- 导入 MIDI（纸带页 → 导入 MIDI）：把 `.mid` 放进 `<游戏目录>/logos_music/`（界面有「打开文件夹」），从列表里选一个，预览后「刻成纸带」或「直接播放」。

## 12. 电子琴（MIDI 键盘）

把 USB 电子琴、MIDI 键盘接到电脑上，在游戏里直接弹所有乐器（钢琴、竖琴、管风琴，以后的手持乐器也一样）。

### 12.1 用法

- 乐器界面的演奏页右下角「MIDI 键盘」：列出电脑上的 MIDI 输入设备（软件合成器、音序器和只能输出的设备不列），点一下连上；名字记进客户端设置 `midiDevice`，以后打开乐器界面时按名字自动连。
- 连着时，**打开某件乐器的演奏页、而且你是演奏者**，琴上弹的音就送给这件乐器：本地立刻发声、别人那里同步、录制成纸带都照常。离开演奏页或关掉界面时自动松开。
- 比电脑键盘多的：真正的力度（钢琴、竖琴、录下的纸带都有轻重）；88 键直接对应，不用换八度；琴上的延音踏板（CC64）就是钢琴的延音踏板；CC120/123 全部松开；管风琴上，琴的音色切换键（Program Change）轮流切六个预设。
- 设置页：刷新、断开；力度曲线（轻 / 标准 / 重）；只听哪个通道（全部或 1–16，Shift 点一下回到全部）；整体移调（±1，按住 Shift ±12，点中间的数字归零）。「试一下」一行显示收到了多少条消息、最近按下的音和力度，不打开乐器也能看出琴有没有连上。
- 拔掉琴后点刷新会显示「琴被拔掉了」；插回来刷新再点一次即可。新插的琴在 Windows 上通常刷新就能看到，看不到时重启游戏。

### 12.2 实现

- `music/MidiInput`（纯 Java）：一条短消息 → 按下 / 松开 / 踏板 / 全部松开 / 换音色；力度为 0 的「按下」当松开，系统实时消息（时钟、主动感知）、触后、弯音暂不处理；通道过滤、移调（移出 0–127 的丢掉）、力度曲线。
- `client/music/MidiKeyboard`：列设备、连接、断开；设备线程收到的消息只进队列（带到达时刻），每帧在主线程翻译并交给正打开演奏页的界面（`MidiKeyboard.Target`）；没有界面在接收时丢掉，计数照记。录制和实时演奏的批内偏移按消息到达的时刻算，不按帧。
- `client/music/MidiDeviceScreen`：设置页。客户端设置 `midiDevice`、`midiChannel`、`midiTranspose`、`midiVelocityCurve`。
- 服务端不用改：实时演奏的速率限制（平均每秒 128 个事件）够快速琶音加踏板用。只读玩家选的设备，不读文件。

### 12.3 验证与限制

- 单元：`MidiInputTest`。客户端：`midi_keyboard_ui` 把 MIDI 消息直接塞进接收器（与设备送来的走同一条路）：没打开乐器时消息被丢掉；带踏板的和弦让三个键亮起、声音引擎在响；力度为 0 的按下与松开都能松开；录下的纸带保留 100 / 80 / 60 的力度和两次踏板；「轻」的力度曲线生效；设置页显示收到的消息。
- **没有用真的电子琴试过**（开发机上没有 MIDI 输入设备）。macOS 上 Java 自带的 MIDI 输入对部分设备不稳；蓝牙 MIDI 要先在系统里配对。遇到问题请提 issue，附上设置页里显示的设备名和日志里 `MIDI keyboard` 开头的几行。
- 以后：弯音轮、调制轮（给小提琴的滑音和揉弦）、表情踏板 CC11（给管风琴的增音箱）。

## 13. 第二批方块乐器：钟琴、钢片琴、管钟、大键琴

和钢琴、竖琴一样：右键打开界面（演奏页、纸带页），纸带槽、红石、多人同步、录制、编辑器、MIDI 导入、电子琴都通用。

| 方块 | 音域 | 形状 | 声音 |
|---|---|---|---|
| 钟琴 `hexen_glockenspiel` | G5–C8 | 一格，钢条琴框架在支架上，旁边搁两支琴槌 | 钢条的自由振动模态（1 : 2.756 : 5.404 : 8.933），硬槌敲出很亮的一下，没有制音、自然衰减 |
| 钢片琴 `hexen_celesta` | C4–C8 | 一格，小立柜：键盘、大理石纹面板、正面镶嵌板、踏板 | 毛毡琴槌敲钢片，木共鸣箱托住基音，甜而轻；有制音与延音踏板，同钢琴 |
| 管钟 `hexen_tubular_bells` | B3–G5（换录音后，原为 G3–C6） | 两格高，胡桃木架挂八根铜管，顶上星辰花牌饰 | 近似谐和的高次模态让音高听得清，上方模态带一点拍频的颤动，余音 6–9 秒，松手不止 |
| 大键琴 `hexen_harpsichord` | F1–F6 | 一宽两深，两层手键盘，白漆琴身、琴盖内侧星辰花镶嵌、音板上金色玫瑰花窗 | 羽管在靠近弦端处拨弦，泛音很多，8′ 与 4′ 两组弦；**不感力度**（按得轻重一样响），松键制音落下，没有踏板 |

- 合成：钟琴 = 铁锭 ×4 + 音符盒 + 木棍 ×2（`I I / INI / S S`）；钢片琴 = 铁锭 ×3 + 音符盒 + 深色橡木板 ×4（`III / PNP / P P`）；管钟 = 铜锭 ×5 + 音符盒 + 深色橡木板 ×2（`CCC / CNC / P P`）；大键琴 = 石英块 ×3 + 线 ×2 + 音符盒 + 深色橡木板 ×2（`QQQ / SNS / P P`）。都在功能方块页。
- 采样最初由 `tools/instrument_samples.py` 合成；2026-11-11 起钟琴、管钟、大键琴改用录音采样（第 15 节），钢片琴仍合成（17 个，每隔小三度一个）。
- `InstrumentKind` 新增 `blockId`、`velocitySensitive`（大键琴、管风琴为否）、`usesPedal`（钢琴、钢片琴为是，其余乐器不理会延音踏板事件）。方块形状：一格的 `SingleInstrumentBlock`，两格高的 `TallInstrumentBlock`（竖琴也改用它），一宽两深的 `LongInstrumentBlock`。
- 重新生成钢片琴的采样后，再跑一次 `tools/instrument_sources.py --only celesta` 更新它的采样表（量响度、定增益）。

## 14. 手持乐器与乐谱架：小提琴、长笛、王室小号

拿在手上边走边弹；放到乐谱架上就成了一件方块乐器，能装纸带、接红石，加入大合奏。

### 14.1 怎么玩

- 拿着乐器右键：举起来演奏（同拉弓那样「使用中」），屏幕底部出现一条演奏条，世界照常显示、不暂停。键位同乐器界面的演奏页（两排字母键是半音阶），←→ 换八度，↑↓ 改力度，Esc 收起；电子琴也能弹。乐器离手、关掉演奏条就收起，所有音松开。
- 声音跟着演奏者走，附近的人都听得到（小提琴、长笛 40 格，小号 56 格）；限速同方块乐器的实时演奏。手持演奏没有纸带和录制，要录下来就把乐器放到乐谱架上。
- 乐谱架：拿着手持乐器右键空架子，乐器放上去，架子上看得到它——小提琴靠在架子脚边、琴弓斜靠在另一侧；长笛横搁在谱台下沿；小号搁在谱台上，王室旗垂下来。拿另一件乐器右键就换过来。放了乐器的架子就是那件乐器：右键打开乐器界面（演奏页、纸带页、录制、编辑器、MIDI 导入），纸带槽、红石启动都和其他方块乐器一样。潜行空手右键把乐器取回（正在演奏的停下）。空架子右键会提示先放乐器；拆掉架子时乐器、纸带、架子各掉一件。

| 物品 | 音域 | 声音 | 合成 |
|---|---|---|---|
| 小提琴 `hexen_violin` | G3–E7（换录音后，原为 G3–G7） | 独奏小提琴揉弦的长弓（录音，p / f 两层） | 丛林木板 ×3 + 线 ×3（` PS / PSP / SP `） |
| 长笛 `hexen_flute` | C4–C7 | 带揉音的长音（录音） | 铁锭 ×3 斜放 |
| 王室小号 `hexen_trumpet` | F♯3–C6 | 直音长音（录音，弱 / 强两层，越响越亮） | 金锭 ×5 + 蓝色羊毛（`  G / GGG / WG `） |
| 乐谱架 `hexen_music_stand` | — | — | 深色橡木板 ×3 + 木棍 ×4（`PPP /  S  / SSS`） |

- 演奏姿势（第三人称，别人看到的一样）：小提琴夹在下巴下、搁在非惯用手一侧的肩上，非惯用手托着琴颈，惯用手横着运弓（在弹时弓来回拉）；长笛横在嘴边、伸向惯用手一侧；小号举在嘴前，王室旗垂在导管下。左手惯用时整幅左右镜像。演奏时两只手原来拿的东西不画。第一人称看到举到下巴、嘴边的乐器，露在演奏条上面（小提琴的弓横搭在弦上）。
- 王室旗：魔女之森的夜蓝底、五瓣金色星辰花、镶红宝石的小王冠、银星、金边、燕尾与流苏，由 `tools/instrument_art.py` 画；另有象牙底、左右分色两种备选（`hexenwald_banner(style)`，`python tools/instrument_art.py <目录>` 会把三种的放大预览写到那个目录）。
- 合成表、物品都在：乐谱架在功能方块页，三件乐器在工具页。

### 14.2 实现

- 声音：第一版在客户端现场合成（`HeldSynth`，带一段起音噪声，试玩时听起来像一下鼓声）；2026-11-11 起换成录音采样，循环点让按住的音一直响下去，见第 15 节。附近有人拿着手持乐器、或打开演奏条时，先把它的采样解码好。
- 同步：`MusicPayloads.HeldNotes`（客户端 → 服务端，一批音）→ 服务端核对手上确实拿着这件乐器、限速、清理 → `HeldNotesOut` 发给附近的人（按乐器的广播距离）。收到的一批同实时演奏一样延后 100 毫秒、按批内偏移排开；声音每 tick 跟到演奏者身上。
- 物品：`HandheldInstrumentItem`（「使用中」不限时、动画为 NONE），右键时客户端打开 `HandheldScreen`。「使用中」本来就同步给附近的人，姿势不用另发包。
- 姿势与画法：`HandheldPoses` 经 NeoForge 的枚举扩展加三个 `ArmPose`（`META-INF/enumextensions.json`），只在「使用中」生效。`HeldRig` 算出乐器的位置（小提琴跟着身体，长笛、小号跟着头）和两只手该到的位置；姿势里两只手臂直接指向手位（蹲下时原版在这之后才加的偏移先算进去），玩家层按同一份位置画乐器（`items/held/` 下的四个物品定义，只供渲染、不是物品，模型不带显示变换），所以手总落在乐器上。
- 乐谱架：`MusicStandBlock`（继承 `InstrumentBlock`），方块状态 `holds` = none / violin / flute / trumpet 决定模型和乐器种类；放上去的那件乐器存在方块实体里（`InstrumentBlockEntity.instrument`）。空架子 `playable()` 为否：不能演奏、不能被占用。`InstrumentBlock.kind(BlockState)` 让同一种方块按状态当不同的乐器。

### 14.3 验证与限制

- 单元：`SampleMapTest`（换录音后取代 `HeldSynthTest`，见第 15 节）。世界测试：`instrument_music_stand`（空架子不能演奏；放上小提琴后成为小提琴；装纸带、红石启动；拆掉时三样各掉一件）。客户端：`music_stand_views`（四个架子正面、侧面、小提琴近景）、`handheld_play_ui`（三件乐器各举起来按三个键：本地 ≥3 路在响、跟着自己；第一人称、斜前方左右、侧面各一张截图；关掉演奏条后放下；模拟另一人手上小提琴的一批音，在那人的位置响、收起时停下）。
- 多人只用模拟的一批音验证过；两个真实客户端、专用服务器没测。音色只能人工试听。
- 以后：手持乐器跟着纸带合奏的节拍弹（显示节拍）；弯音轮、调制轮（滑音、揉弦深浅）；更多手持乐器（大提琴要坐着、单簧管、圆号）。

## 15. 换用录音采样（2026-11-11）

维护者试玩手持乐器时听到每个音开头有一下像鼓的声音（合成时叠的起音噪声），决定趁此把音源换成公开采样库的录音。
来源、许可、每件乐器用了什么、怎么处理、以后备用的乐器，都在 [乐器采样](INSTRUMENT_SAMPLES.md)。要点：

- 钢琴：Salamander Grand Piano（Yamaha C5，CC BY 3.0，**须署名**，见 `CREDITS.md` 与「音乐厅音源」资源包根目录的 `NOTICE.txt`，见第 16 节），30 个音 × 5 层力度。
- 竖琴、钟琴、管钟、大键琴：VCSL（CC0）；小提琴、长笛、小号：VSCO 2 CE（CC0）。钢片琴两个库都没有，仍合成；管风琴仍按音栓现场合成。
- 力度先选力度层（音色不同），再定音量；各层在交界处一样响，换层时只换音色。
- 小提琴、长笛、小号的长音用循环点（OpenAL 的 `AL_SOFT_loop_points`）一直响下去，没有合成时那一下起音噪声；松键淡出。
- 大键琴松键时有拨子落回的一下；钢琴松键时低音淡出慢、高音快。
- 音域变了两处：管钟 B3–G5（真实管钟 C4–F5），小提琴到 E7；超出的音按八度挪进来。
- 采样不再写进 `sounds.json`，按采样表直接播放，弹到才读进内存。

## 16. 两层音源与第六轮乐器：中提琴、大提琴、低音提琴、双簧管、巴松管、定音鼓（2026-11-11）

### 16.1 两层音源

换成录音后音色好了很多，但录音放进模组 jar 会让模组越来越大（以后各族聚落还要加特色乐器）。维护者的决定：不降音质、不减层数，
**拆成两层**——模组本体只带体积很小的合成音（15 件共 3.4 MB），录音挪到单独发布的「音乐厅音源」资源包（约 22 MB）。
装上并启用资源包就是音乐厅的录音，不装也能弹。以后加新乐器都做两层：合成的进模组，录音的更新到资源包。
做法与格式见 [乐器采样](INSTRUMENT_SAMPLES.md)。

### 16.3 实现

- 种类：`InstrumentKind` 末尾加 VIOLA、CELLO、DOUBLE_BASS、OBOE、BASSOON、TIMPANI（网络按序号传，只能加在末尾）。
  `handheld()` 认三件手持，`seated()` 认大提琴、低音提琴；只有弓弦、管乐的采样带循环点。
- 两层音源：`SampleMap` 多了 `format`、`quality`；`client/music/SampleMaps` 按资源包从上往下取第一张读得懂的表；
  `sourceLabel()` 给界面用。
- 座位：`InstrumentSeat`（看不见的实体，不存盘、打不坏）。`SeatedInstrumentBlock`（继承 `TallInstrumentBlock`）空手右键时在琴后
  生成座位、让玩家骑上；座位的位置就是演奏者双脚的位置（`SeatedInstrumentBlock.feet`，按方块朝向转过去，抵消玩家自己 0.6 格的骑乘挂点）。
  身体朝向固定为琴的朝向，头最多转 75°（同原版的船）。没人坐了、琴不在了，座位自己消失。
- 姿势：`HandheldPoses` 多三个手持姿势和两个坐姿（`META-INF/enumextensions.json`）。骑在座位上时，玩家层把双手原来拿的东西清掉、
  右臂姿势换成大提琴 / 低音提琴：两腿（大提琴分开前伸、低音提琴伸直），右臂瞄向弓根，左臂瞄向指板。
  原版手臂是直的：`HeldRig.seated` 让右手瞄准弓根该在的位置，手实际到哪弓根就在哪，弓总从琴弦上的那一点穿过（弓毛贴着琴弦）；
  左手沿指板从琴枕往下，找第一个离肩正好一臂远的点（落在指板下段，像高把位）。
- 美术：`tools/instrument_models/strings.py`（2026-11-14 重做；当初是 `tools/instrument_art.py` 的 `orchestra()`、`handheld()`）。大提琴、低音提琴按竖直的样子画在琴自己的坐标里，再整体后仰、
  向左倾（26.1 的模型元素认 x/y/z 欧拉角转动，`rigid()` 把整组元素当刚体转，已带转动的元素与它合成）；琴的摆放与 `HeldRig` 的
  `CELLO` / `BASS` 布局是同一组数（脚本运行时打印弓根离右肩的距离、左手的位置，核对直臂够不够得着）。
  中提琴是小提琴的模型换成原版红树木板的清漆；资源包图标（深红幕布、金色帷幔、聚光灯下一把大提琴）也由这个脚本画。

## 17. 合奏哑音、管风琴不出声与音高错乱（#243，2026-11-11）

维护者试玩时报：全乐器合奏时有几件乐器有时不出声，甚至一件件哑掉；管风琴有些键不出声；有些乐器音调错乱（#243）。
全面检查后找到的原因和改法：

| 现象 | 原因 | 改法 |
|---|---|---|
| 合奏时乐器一件件哑掉 | 服务端按 tick 算纸带位置（tick × 50 毫秒），客户端按真实时间放。服务端一卡（光影、区块加载时很常见），两边的时钟就差开；服务端每 5 秒的心跳包一到，客户端发现差了 150 毫秒以上就重新定位——**把这件乐器正在响的音全部掐掉**，按下得早的长音也不再补上。每件乐器的心跳按它开始播放的那一刻排，所以是一件接一件地哑 | 服务端改按真实时间算位置（同客户端）；客户端收到心跳只挪时钟、正在响的音照常响、待松开的音一起挪，差了 3 秒以上（服务端那边真的跳了位置）才重新定位 |
| 合奏开头、少用的音偶尔不响 | 纸带开始放时只预读了手持乐器的采样，方块乐器第一次用到某个采样才解码；十几件乐器同时开始时解码排队，短音晚到、甚至松开时还没响 | 纸带和乐器一确定，就把这卷纸带要用到的采样（按声部移调、力度挑出来的区）先解码好；晚了 0.4 秒以上的音不补弹，不会卡一下之后一齐涌出来 |
| 合奏时某件乐器的长音被掐断 | 所有乐器加起来到了上限（默认 96 个音）时，停的是全局最旧的音——常常是别的乐器仅有的一个长音 | 先从有尾音的乐器里停，再从发声最多的那件里停 |
| 管风琴有些键不出声 | 换资源包（比如启用音乐厅音源）、F3+T、换音频设备都会重启声音引擎，OpenAL 的上下文换新。管风琴自己留着的缓冲还是旧上下文的编号，**重启前按过的键**交给引擎的是无效（甚至是别的声音）的缓冲，就不出声 | 声音引擎重启时（`SoundEngineLoadEvent`）丢掉这些缓冲的引用，下次用到时重做；预读、纸带的采样也重新解码 |
| 管风琴的音色在键盘上忽变，像突然低了八度 | 每个采样的各排管各取随机初相位，落在同一频率上的分音（8′ 的二次泛音和 4′ 的基音）在相邻采样里一会儿加强一会儿抵消：晨祷预设里 8′ 基音和上方八度的强弱比在相邻采样间最多差 23 dB | 初相位只由分音相对 16′ 基音的倍数决定，同频分音在每个键上都以同样的相位叠加：相邻采样之间不到 3 dB。全奏里混合音栓在 C6、C7 按八度折回的两处仍会变，同真的混合音栓 |
| 钟琴、管钟等在默认位置弹音阶忽高忽低 | 超出音域的音逐个按八度折进来（`fold`）：钟琴音域 G5–C8，默认键盘从 C3 开始，C–F 被抬到第六组、G–B 留在第五组，fa→sol 往下跳了十度；纸带、电子琴、别人的演奏都走这一步。松键也按折过的音高找，不同的键会互相止音 | 键盘按乐器的音域摆（钟琴从 C6、低音提琴从 C2，钢琴等仍从 C3），换八度只到键盘还碰得到音域为止，音域外的键画暗、不出声，电子琴同样；纸带按声部整体移八度（能弹到的音最多、保留音程），声部比乐器还宽时剩下的个别音才折叠；每个音记着原来的键，松键、重弹按它找 |

采样本身没有问题：新加的 `tools/instrument_audit.py` 量了两层音源每件乐器的每个采样，都在记的音高 ±25 音分以内
（最大 20 音分，是小提琴的揉弦和钢琴的伸张调律），音域里每个音、每个力度都取到 4 个半音以内的采样。

### 17.1 验证

- 单元：`MusicRollTest.wholePartsMoveByOctavesToFitTheInstrument`（钟琴放 C3 大调音阶整体上移三个八度、七个音一个比一个高；
  本来就在音域里的声部不动；比乐器还宽的声部取能弹到最多的移法）、`KeyLayoutTest`（每件乐器打开时键盘与音域重合得最多，
  原来的起点合适就不变；换八度停在还碰得到音域的地方）、`OrganSynthTest.octavePartialStaysBalancedAcrossKeys`
  （晨祷、合唱、全奏在混合音栓折回之前，8′ 基音与上方八度的强弱比在相邻采样之间不到 3 dB；换回随机相位时这个测试失败，差 23 dB）。
- 客户端：`ensemble_resync_ui`（大提琴放 6 秒长音，中途模拟一个偏了 0.4 秒的心跳，长音仍在响；偏 5 秒时才重新定位）、
  `organ_reload_ui`（按一个管风琴键、重启声音引擎、再按同一个键，仍在响）；其余乐器场景回归。
- 音高：`tools/instrument_audit.py` 两层 29 项全部干净。
- 没有在服务端真的卡顿、真的多人合奏的环境里试过；心跳偏差、声音引擎重启都是在测试里模拟的。

## 18. 乐团：指挥台、指挥棒与统一演奏（2026-11-11）

指挥台（两格宽）、指挥棒、按总谱自动分声部、共用一个时钟的合奏、跟着拍号和响度的指挥手势、选中声部的描边，
说明见 [ORCHESTRA.md](ORCHESTRA.md)。乐器这边的改动：方块实体记着自己的乐团（`orchestra`，存档）和正在跟着哪座指挥台演奏
（`conductedBy`，不存档；这时自己的纸带、红石不起作用）；乐器被拆、乐谱架上的乐器被拿走或换掉时通知指挥台；
纸带末尾可以带一段速度与拍号表（没有变化的纸带与旧格式逐字节相同）。
