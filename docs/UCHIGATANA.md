# 神狐打刀：动作规划

整理时间：2026-11-02。武器素材是 `art/fox_uchigatana/v02`（神狐·量产打刀，四套刀装），使用者是神狐 NPC（`MinecraftLogosMod/fox_model/divine_fox`）。动作按 [战斗骨架与兼容性规范](COMBAT_SKELETON.md) 制作，玩家和神狐共用同一份编排。本页只管动作；格挡、弹刀的判定和数值以后另做。

## 1. 素材检查（v02）

符合规范的部分：

- 四套配色共用同一套几何和 UV（32×96），交付自带 combat 网格 `combat/weapons/fox_uchigatana_*.json`，字段与长剑相同（`texture`、`texture_size`、`cubes`，`part` 分 `weapon` / `sheath`）。
- 坐标约定：刀尖 +Y、刃 +X、厚度 Z，网格原点在柄与刀镡之间；`source/assembly.json` 给出双手握点：主手 y=0.65、副手 y=−1.1。
- 刀和鞘挂在 TLM 参考骨架的 `Weapon` / `Sheath` 下；归鞘时刀与鞘同一变换，鞘口在 y≈2.23，刀尖完全出鞘需要后退约 13.3。
- GeckoLib 5.5.2 解析、烘焙通过；归鞘无穿插。

接入前要处理的：

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 神狐模型是 2 倍制作，观察工程里刀也是 2 倍，刀长约是神狐手臂的 2.8 倍（玩家按 1 倍时约 1.4 倍），拔刀、收刀时手够不到。 | 已定：神狐的刀按 **1.6 倍**挂（约为手臂的 2.2 倍），鞘口位置、佩刀朝向不变；拔刀、收刀时神狐的左手把鞘向后猛拉约 0.6 臂长、转开 50°。 | 模型并入 `Weapon` / `Sheath` 时按 1.6 倍放置网格。 |
| 2 | 武器缩放现在写在玩家骨架上（`player_tp.json` 的 `weapon_scale` 0.8，长剑用）。 | 打刀按 1.0 制作，与长剑不同。 | 接入时给武器网格加可选的 `scale` 字段，乘在骨架缩放上。 |
| 3 | 神狐素体里没有 `Weapon` / `Sheath` 骨骼，佩刀位置只在观察工程里。 | NPC 动画要驱动这两根骨骼。 | 接入时作为配件部件并进模型，枢轴与观察工程一致。 |
| 4 | 物品、物品模型、图标都还没有注册（`variants.json` 的 `integrated` 为 false）。 | 游戏里还看不到。 | 动画定稿后与 Java 一起做。 |

## 2. 能从 TLM 借用什么

TLM 1.21 分支的 `maid.animation.json` 有 100 段动画，刀相关的只有单手的 `hold_mainhand:sword` 和 `swing:sword`（1.5 秒，带 `v.jump`、`v.random` 等 Molang），双手持刀、拔刀、收刀、格挡都没有。所以：

- **打刀动作全部自制**。
- **神狐的移动动作可以借**：`walk`、`jump`、`attacked`、`ladder_*`、`swim_stand` 与森林精灵一样直接借用（署名见 CREDITS.md）；`run` 用了 `ysm.head_pitch` 等变量，要等驱动支持。持刀时这些动作只占下半身和头，双臂与刀由打刀动作覆盖。

## 3. 玩法与状态机

左键连招，右键按住立刻格挡，打断正在进行的连招。用现有的招式状态机（COMBAT_SKELETON.md 第 5 节）表达：

```
拔刀 draw ──► 待机 idle ──左键──► 一 slash_1 ─► 二 slash_2 ─► 三 slash_3 ─► 四 slash_4 ─► 回到一
                │  ▲                  │ 任何时刻右键（不排队，立即）
                │  └──松开右键────────┤
                └──右键──────────────► 格挡 guard（循环）
                                        │ 进入格挡 0.3 秒内被击中
                                        ▼
                                      弹刀 parry ──左键──► 反击 riposte ─► idle
                                        └─结束─► 仍按住右键回 guard，否则回 idle
切走物品 ──► 收刀 sheathe ──► $clear（恢复原版）
```

- **“马上”格挡**：每个攻击招式都带 `{"input": "use_press", "to": "guard", "window": [0]}`（不排队，立即切换），`guard` 的 `blend_in` 取 0.05 秒左右，画面上没有原版盾的举盾前摇。原版盾的延迟来自物品的 `blocks_attacks` 组件（`block_delay_seconds`）；打刀可以直接用这个组件并把延迟设为 0，伤害减免仍走原版流程（兼容性规则 2）。
- **弹刀**：需要新增一种“被击中”输入，由服务端在格挡开始 0.3 秒内受击时触发，转入 `parry`；`parry` 里左键转 `riposte`。弹开、不耗耐久、禁用对方武器等效果以后做。
- **标记**：每段攻击都标了 `contact`、`cancel` 和 `input_open`（第 4 节表格），按 COMBAT_SKELETON.md 第 6 节交付。

## 4. 动作清单

### 4.1 玩家与神狐共用（第一版已做）

| 动作 | 时长 | 标记（秒） | 内容 |
|---|---|---|---|
| `draw` | 1.0 | cancel 0.85 | 右手越过身体握柄，左手推鞘口、拉鞘；刀横向拔出抽成一刀，挽刀花收进待机 |
| `idle` | 2.4 循环 | — | 下段单手构：右手持刀斜指前下，左手扶鞘口，右脚在前的半身站姿，带呼吸 |
| `slash_1` | 0.48 | input_open 0.08 / contact 0.15 / cancel 0.30 | 右手单手逆袈裟：从右后下方撩向左上，刀越过头顶 |
| `slash_2` | 0.52 | 0.08 / 0.18 / 0.32 | 双手左袈裟：左上斩到右下 |
| `slash_3` | 0.52 | 0.08 / 0.20 / 0.34 | 单手横一文字：先向右拧身、左手前指，再大幅横扫到左后 |
| `slash_4` | 0.78 | 0.10 / 0.38 / 0.58 | 双手举过头顶，踏步弓箭步唐竹割，压低收势停顿 |
| `guard` | 1.6 循环 | — | 右手握柄，左掌托刀背，刀斜架在身前 |
| `parry` | 0.42 | contact 0.04 / cancel 0.12 | 刀向右上外崩，左手离刀，留出突刺架势 |
| `riposte` | 0.42 | contact 0.09 / cancel 0.24 | 刃朝外的平突，弓步前冲 |
| `sheathe` | 2.3 停在末帧 | — | 血振 → 手腕转刀两圈（刀在身体右侧竖直面里转，刀尖前→下→后→上）→ 刀横到身前、刀背搭在左手鞘口 → 刀尖入鞘、缓推到底 → 残心后松手 |

四刀的刀路依次是：右下→左上、左上→右下、右→左横、上→下竖，一圈收尾回到起手位置，可以无限循环。

### 4.3 玩家另需

- **第一人称**：长剑的第一人称是单独一套动作。打刀的第一人称还没做，可以用同一份编排在第一人称骨架上烘焙，再单独调镜头内的位置。
- **只显示双臂和躯干转向**：按兼容性规则 3，玩家只替换双臂，躯干只跟 `UpBody` 的旋转；编排里的髋部下沉、弓步只在 NPC（以后的全身代理）上看得到。动作在这个限制下也成立，只是玩家版少了腿部的力度。

## 5. 制作方法

`tools/combat_author.py` 与 `tools/uchigatana_moves.py`：动作写成“编排”（刀柄位置、刀尖与刃的方向、躯干转向、脚的位置、左手握法），双臂、双腿用两段式逆运动学解出，手腕按握法对齐刀身，再分别烘焙到玩家参考骨架和神狐骨架。

- **没有腕关节**：玩家模型没有手腕，手与前臂固定成一体，只有肩（三向）和肘（弯曲加前臂自转）。手送到握点后，逐帧在“手肘绕肩—握点连线的转角”里找最贴合的一组，前臂自转让拳心尽量正对刀柄。袖子是方块，前臂连续自转会和上臂在肘部错开、棱角穿插（看起来像破面），所以前臂只转 0°、±90°、180°（正方形截面转 90° 的整数倍仍然对齐），换档有代价、很少发生。手肘偏离默认朝向、抬过肩下方都扣分，第三人称姿势才自然。刀仍按编排运动，剩下的偏差表现为刀柄斜着穿过拳心（烘焙时按动作打印平均与最大偏角）。手肘位置逐帧连续，不会突然翻面。神狐同样处理。
- 左手握法可在一段动作里切换（双手握柄、扶鞘口、托刀背、自由），切换时自动平滑过渡；刀可以“入鞘”并沿鞘身滑动，鞘口跟着左手推拉、旋转。
- 神狐的静止外张角（上臂约 18°）在导出时扣除，满足 GeckoLib“动画角度叠加在静止角度上”的规则。
- 比例差太多时，关键帧里可以写只对某副骨架生效的覆盖（例如 `fox=dict(saya_off=...)`）；神狐的拔刀、收刀就是这样加大拉鞘幅度的。
- 烘焙时检查手能不能够到目标，够不到的时段会打印出来。
- 预览由脚本离线渲染（不是游戏截图），刀尖轨迹画成红线：

```bash
uv run --with numpy --with pillow python tools/uchigatana_moves.py "<Minecraft MOD 目录>" "<输出目录>" [动作名…] [--gif]
```

输出：每段动作一张总览图（玩家与神狐、两个视角、含标记帧），`--gif` 另出动图；同时把玩家的两份动作写进 `assets/logos_dimension/combat/animations/uchigatana_{tp,fp}.animation.json`，带 `timeline` 标记。第一人称用 `player_fp.json` 烘焙，根骨与长剑第一人称一样靠右，武器按 0.58 × 1.25 缩放；打刀架势低，第一人称的手统一前移、抬高（`reach`），待机改为中段单手构（`IDLE` 的 `fp` 覆盖），否则刀在画面外。

物品资源用 `tools/import_uchigatana.py <美术 v02 目录>` 导入：刀的贴图改名为 `*_rig.png`，网格加 `scale: 1.25`，物品栏图标按各配色的柄、镡、刀身颜色生成 32×32 像素画（占位，可换成美术画的图标）。

## 6. 游戏内（试玩版）

- 四件物品 `fox_uchigatana_ink` / `vermilion` / `indigo` / `wood`，铁剑的伤害与耐久、攻速 1.8，放在附属的创造模式物品栏。
- 招式文件 `data/logos_dimension/combat/movesets/uchigatana.json`：第 3 节的状态机原样写出；`guard` 的 `block` 转移窗口 `[0, 0.3]`。
- 格挡用原版 `blocks_attacks` 组件，参数与盾相同，只是延迟为 0；弹刀由 `LivingShieldBlockEvent` 触发，接受时不耗耐久。按住右键时也能点左键接突刺（原版会吞掉这次点击，客户端先取走发给服务端）。
- 长剑与打刀共用运行时：物品通过 `CombatWeapon` 给出网格、动作和招式文件。
- 试玩场景 `client/UchigatanaView`（`-PldTest=group:uchigatana`）：实际按键走完拔刀、四段连招、出刀中按右键立即格挡（服务端当刻 `isBlocking`）、刚架刀被击中弹刀（不掉血、不耗耐久）、按住左键接突刺并命中、超过 0.3 秒只格挡且照常耗耐久、切槽收刀转刀，第一与第三人称截图。
- 物品模型：物品栏和展示框用平面图标；手持、掉落和魔力缠绕用立体模型，由刀网格的刀身部分平移 (8, 1, 8) 生成，缠绕特效贴在刀身上。
- 玩家的手改为原版那样的一整块（长剑同样生效），不再是掌、四指、拇指拼成的拳头。
- 还没做：弹开后禁用对方武器；神狐 NPC。
