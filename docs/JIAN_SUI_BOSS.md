# 剑祟：Boss 战

整理时间：2026-11-22。附属的第二个 Boss。前两个阶段在太玄灵境深渊底下的雾底场地打（[TAIXUAN.md](TAIXUAN.md)）。第三阶段在场地正下方新挖的空洞里打，空洞布置成场地正在塌落的样子。模型和现有动作见 [JIAN_SUI.md](JIAN_SUI.md)，招式、命中、防御沿用白梅的做法（[SHIRAUME_BOSS.md](SHIRAUME_BOSS.md)）。

本页先写设计，实现时再逐节补上做法与测试。

- 标了「补充」的，是维护者没有提、我加的设定。维护者 2026-11-22：「可以都加，只要风格符合」。
- 维护者 2026-11-22 在稿子上的批注和第 20 节的决定，已经写回各节；第 20 节留了一份对照。第 19 节是实现进度。

## 1. 流程

```
雾底石台上一堆散架的残骸，贯穿古剑竖插在中间
   │ 有人走近、碰剑或者打它
   ▼
登场（约 8 秒）：散架倒着放，碎片飞回、拼成剑祟 → 竖瞳滑过来看人 → 标题
   ▼
第一阶段「剑客」：手中古剑，有起手、能弹反的剑招；掷剑回旋、背剑点射；不停地逼人
   │ 第一条血清空
   ▼
离体（约 6 秒）：五柄背剑一柄柄拔出，悬在身后
   ▼
第二阶段「御剑」：五剑远程刺击、落剑、剑笼；掷剑时从空中接一柄背剑换着用
   │ 第二条血清空
   ▼
裂地（约 11 秒）：手中古剑插进地板 → 发光的裂缝爬满场地 → 光漫上来，画面全白
   ▼  白屏里送进场地正下方的空洞
第三阶段「坠渊」：看上去整片场地塌了、正往下掉。玩家在最低的碎块上，剑祟在最高的一块上；
   玩家踩着碎块往上爬，剑祟往下射巨剑；掉下去就黑屏、受一点伤，回到到过的最高一处落脚台
   │ 爬到它身边，近战打中一下
   ▼
终结（约 7 秒）：黑白处决，玩家的剪影拿着剑飞身刺向剑祟的剪影
   │ 趁画面黑白的这一下换场景，回到上面的雾底场地
   ▼
   从「剑已经刺进胸口光缝」接着演：撬三下，贯穿古剑从头顶崩飞出去，剩下的散架
贯穿古剑插在场地上（以后做成奖励）
```

## 2. 场地

### 2.1 雾底场地（第一、二阶段）

场地已经生成好了，是 `tools/taixuan_abyss.py` 的 `shaft()` 和 `arena()` 画的。

中心在结构起点正下方，坐标是（起点 x，−16，起点 z），`/locate` 给出的就是这个 x 和 z。下面的高度都是方块所在的 y，人站在方块上时，脚在高一格的位置。

- **地面**：y=−16，半径约 50（边缘 ±3.5）。磨制深板岩和深板岩瓷砖一圈一圈相间，每圈 4 格宽，零星夹着裂纹瓷砖和苔石。
- **石台**：分三层。
  - 平滑石 r≤7，y=−15；
  - 磨制闪长岩 r≤4.5，y=−14；
  - 3×3 玄铁心，y=−13，7 级光。
- **八根断柱**：立在半径 28 的圈上，每根 3×3，高 5–14。柱身是石砖和裂纹石砖，每 5 层夹一道磨制安山岩，柱顶放一盏魂灯。截图里柱子发黄，是渊雾的雾色染的。
- **中央铁链**：13 节玄铁链环，每节长 7、宽 3，相邻两节转 90°，每 5 格一节。铁链从链台底下一直垂到 y=−11，下面只空一格就是玄铁心。
- **栈道**：沿石壁盘下来，到底时离中心约 48 格。接着地面上有一条路线，走到离中心约 10 格的石台前。

正中被铁链占着，站不下四格高的剑祟。所以残骸、插剑的位置，以及剑祟「回到石台」时的落点，都在石台上、铁链旁边的同一个点。

有两个范围：

| 范围 | 大小 | 用途 |
|---|---|---|
| 剑祟活动范围 | 离中心 40 格以内，脚在 y −15 到 −3 | 剑祟只在这里面走、跳 |
| 战斗范围 | 离中心 60 格以内，y −16 到 +15，加上下面的空洞 | 决定锁定谁、谁看得到血条，以及 30 秒没人时重置 |

栈道最后一圈离中心 45–48 格，柱顶上的人脚在 −1 左右，这两处剑祟都砍不到，它用飞剑打（第 5.3 节）。

### 2.2 场地下方的空洞（第三阶段）

维护者要的是：地板下面再挖一个空洞，一直深到基岩上面。具体做法如下（补充）。

**在模板里挖。** 空洞放进太玄的模板，由 `tools/taixuan_abyss.py` 新加的 `cavity()` 画出。不在运行时挖，因为 AGENTS.md 只批准太玄用 Java 做选址检查。

**要动哪些模板：**

- 现在模板最底一层是 y −24 到 3，场地地面就在这一层里。原版拼接不放超出世界底（−64）的部件，按 28 格对齐的话，只能再往下加 −52 到 −25 这一层。
- 要挖到底，就在中间 3×3 列下面加一层 9 个 28×35×28 的非立方模板，范围是 y −59 到 −25。
- 最底一层中间的 9 块也要重新导出：空洞顶部 −24 到 −20 的空气、新加的洞顶、四周的石壁都在这 9 块里。
- 一共动 18 块，其余模板和锚点、起始高度都不动。

**空洞的尺寸：**

- 内半径 36，空气从 y −57 到 −20（原稿是 34；外面那一层的几层壳、绕路都要地方，加到 36，石壁外沿 39 仍在 3×3 列以内）。
- 底写两层（−59、−58），再往下就是可能出现基岩的那几层。
- 顶：在现有的 −17、−18 两层深板岩下面再加一层 −19。
- 四周用 3 格厚的层理石壁封住。这个深度有含水层（−54 以上是水，以下是岩浆）和洞穴。
- 空洞里看不见天光。看不见的光源方块（原版 `light`）也写进模板，放在碎块和只看的碎块旁边。

**结构会转，坐标要换算。**

- 整座太玄按原版拼接，随机转 0°/90°/180°/270°，空洞里的东西也跟着转。
- `taixuan.py` 把空洞的布局按画布坐标写进 `taixuan_manifest.json`：起点碎块、顶块、路线顺序、只看的碎块的位置、光源。
- 运行时取根部件的位置和旋转（同世界测试里的 `Site.pos`），存进战斗记录。传送、镜头、补回方块、客户端画碎块，都用这同一个换算。

**代价（估算）：**

- 新加 9 个模板，重新导出 9 个，约 18 万格（主要是空气）；
- 结构文件大约多 0.45 MB，自然生成多 1–2 秒；
- 审计和 `TaixuanDataTest` 里有几处假定「整齐的立方网格」，要跟着改；
- 另加空洞的世界测试（封得住、里面没有水和岩浆）和一个机位。

**空洞里有什么：**

- **写进模板的**：能踩的东西，包括起点碎块、垫脚石、剑祟所在的顶块，用的方块和上面的场地一样（第 10.1 节）。
- **不进模板的**：只看的碎块是第三阶段才出现的画面（第 13 节）。

**有人从别处进空洞。** 地板到洞顶只有 3–4 格，有人提前挖下去能进到空洞里，在里面搭东西。处理方法是：

- 战斗开始时（登场那一下）把空洞按模板整块重放一遍，玩家放的东西、水、岩浆都清掉。运行时写方块，照 Crater 直接写区块数据、按区块重发。维护者 2026-11-22 批准（第 20 节第 1 条）。
- 第三阶段里，不是经裂地或者踩裂缝进空洞的人（比如从上面挖下来的），一律白一下，送到起点碎块。

**旧存档。** 维护者 2026-11-22：放弃旧存档，开发中不考虑。已经生成的太玄灵境没有空洞，也不去识别。

**已经做好的（第 17 节第 2 步）。** `tools/taixuan_cavity.py` 画空洞，`taixuan.py` 导出，`audit_taixuan.py` 和世界测试 `taixuan_cavity` 检查（第 18 节）。实际排出来的布局见第 10.1 节；只看的碎块的方块清单和摆放另写在 `assets/logos_dimension/jian_sui/fall_debris.json`，只给客户端画。

## 3. 登场：散架倒放

### 3.1 残骸怎么进世界

太玄模板里不许有实体，所以残骸在运行时放：

1. 有玩家走进太玄起点附近时，服务端用 `structureManager().getStructureWithPieceAt` 取到结构起点。
2. 以起点所在的区块为键，查战斗记录 `jian_sui_arenas`。
3. 没有记录时，在石台上铁链旁边放一次残骸，记下它的 UUID。残骸不会消失，推不动。

同时记下根部件的旋转（第 2.2 节）。

### 3.2 平时和开场

- **平时**：残骸就是剑祟本体，摆成散架动画最后一帧的样子：面具碎片仰面朝天，背剑和衣摆散在地上，贯穿古剑竖插在中间。它打不坏，没有血条（补充）。
- **有人走进 16 格**：残骸里两只眼睛亮一下（琥珀色），碎片轻轻一颤；人走开就暗回去。不出任何文字。
- **开场**：有人走进 8 格、右键贯穿古剑，或者打它。

开场过场给每个在场的玩家各播一份 `CameraShots`，带遮幅和电影蒙版。过场期间玩家不受伤，剑祟不动。

| 时刻 | 镜头 | 剑祟 |
|---|---|---|
| 0 | 高处远景，石台在画面中央 | 魂灯一盏盏暗下去一半，地面低低地震，碎片发抖（补充） |
| 1.5–4.5 秒 | 低机位，慢慢绕半圈 | 散架倒着放（拉长到 3 秒）：纸符最先飘起来，衣摆、躯干、双臂、头一块块飞回去拼上，背剑插回背上，手中古剑从地上跳回右手。贯穿古剑不跟着倒放：1.5 秒时它自己从地里拔出来，升到胸口的位置停住，等身体拼上来 |
| 4.5 秒 | 面部特写 | 面具最后合拢，胸口光缝亮起 |
| 5 秒 | 同上 | 双眼亮起，竖瞳从正中慢慢滑向镜头，头不动 |
| 6 秒 | 镜头拉回到玩家肩后 | 起势 |
| 6.5 秒 | 画面正中出现大字「剑祟」，下面一行小字「封印的恶念剑骸」 | |
| 7.5 秒 | 标题淡出，镜头回到玩家，遮幅收起 | |
| 8 秒 | 开打，血条出现 | 开始行动 |

**动作怎么来**：

- 倒放、残骸的静止姿势、散架，都在仓库的几何上算，走 `art/jian-sui-model-v6/source/adjust_pr280.py` 那条路：零件表是 `PIECES` 加上 `Skirt`、`WaistBridge0–7`。
- 不要直接跑 `collapse_anim.py`。它读的是 v6 的旧骨架，跑出来腰部零件又会悬在半空。
- 贯穿古剑、胸口光缝、双眼这三条轨道按上表单独给，不取倒放。

## 4. 血条与阶段

- **血条样子**：原版 Boss 血条，名字「剑祟」。第一阶段黄色（眼睛的琥珀色），第二阶段蓝色，第三阶段白色、只剩一丝（补充）。
- **血量**：第一阶段 450，第二阶段 550，各比白梅多 50，写在实体属性里。按开场时在场的人数加血：每多一人 +50%，最多 ×3（同白梅）。
- **前两个阶段不会死**：
  - 血掉到 0 时停在 1，开始转阶段。
  - 每刻受到的伤害有上限，不超过当前这条血的四分之一。
  - Logos 的处决、爆裂魔法这类直接把血打满或者每刻补刀的，也按这个上限算，所以过场不会被跳过。
- **第三阶段不掉血**：所有伤害都不算，只有近战打中一下会触发终结（第 11 节）。
- **谁看得到血条**：在战斗范围里的人（两层都算）。存档、区块卸载时的处理照白梅（`stopSeenByPlayer`），不然血条会一条条叠起来。
- **防附身**：拴绳拴不住；加进 `#c:bosses`，不能被附身。
- **防化身和召唤**：Logos 的化身和召唤看的是击杀数。终结时剑祟用 `discard` 移除，不算击杀，所以生存模式里永远凑不够解锁的击杀数；创造模式本来就不限。
- **其他 Logos 效果**：不能被定住时间、不能被闪现挪走、手里不能被塞东西（第 5.5 节）。

## 5. 共同规则

### 5.1 看人与起手

- **看人只转眼珠。** 头不跟着人转，动作里本来就有的小幅头动保留。竖瞳在眼眶里平移，横向约 ±1 制作单位，竖向 ±0.24（`eye_tracking.json` 里的椭圆）。超出椭圆的角度，靠整个身子转过去补。
- **视线就是仇恨**（补充）。多人时一看就知道它在盯谁。
- **起手。** 每一招都有看得出的起手（引剑、绕步、腾身、剑尖转向），然后一下挥出。挥出前的最后一刻：
  - 竖瞳一下锁死在目标身上；
  - 双眼闪一次琥珀光；
  - 一声短促的剑鸣。

  这对应白梅的红光，换成了它自己的颜色。连续招式只在第一刀闪。
- **飞剑的起手。** 剑先停住，剑尖转过来对准目标，一道光从剑柄跑到剑尖，然后射出。看剑尖就知道往哪躲。
- **现有三招不改。** PR #280 的踏风、回风，起手里挥得比出手还快（起手剑尖每秒 52–54 格，出手 28–41 格）。维护者 2026-11-22：不是非要所有招式都能看清，有时候快到看不清也是一种招式。闪光照样在出手前的最后一刻。

### 5.2 命中与防御

照白梅的 `ShiraumeStrike` 那套来，先抽成共用的代码（第 17 节）：

- **格挡和弹反。** 砍中时先走一次格挡判定。盾牌、打刀、流火、黑钢长剑都能挡；带弹刀的武器在窗口内算弹反。
- **没挡下。** 造成物理伤害（维护者定），走原版的生物近战伤害，护甲照算。白梅没挡下时是奥秘伤害，不看护甲，所以抽出来的时候，元素要改成参数。
- **破盾。** 回风的横掠、飞燕的落剑、剑笼里那一刀，挡下来却没弹反时，手里格挡的东西 5 秒用不了。流火例外（同白梅）。
- **不能弹反的。** 落剑（第 8 节）只能躲，或者举盾硬挡。
- **飞剑也算近战。** 伤害来源写成「飞剑打的，剑祟是主人」：盾的朝向按飞剑的位置算，弹反时僵住的还是剑祟。这也要在抽共用代码时加成参数。

### 5.3 压制：不给吃东西的机会

剑祟一直在逼人。

- **按距离选招。** 每招按自己够得着的距离出手：踏风 2.8 格以内，回风 2.3 格以内，飞燕约 3 格（腾身时往前跃 2 格）。离得比这远时，它先滑到这个距离再出手。
- **按位置选招。**
  - 10 格以上、在栈道或柱顶上够不着，或者跑出了它的活动范围：用背剑点射（第二阶段换成飞剑），同时往那边滑。
  - 4–10 格：也可能掷剑。
- **出招间隔。** 从上一招开始时算起（同白梅），招与招之间基本没有空档。第一阶段收势后只隔 0.4–0.8 秒；第二阶段它收势时，飞剑会补上。
- **读吃东西**（同白梅 4.10，另加远程版，补充）。16 格内有人开始吃喝：
  - 离得近：它贴过去，算好时刻，让第一刀落在他吃完之后 5 刻；
  - 离得远：让一柄飞剑在同一时刻到。
- **能吃东西的窗口：**
  - 弹反它的独立招式之后：仰身僵住 1.8 秒；
  - 掷剑落空之后：空着手站 1.5 秒才去拔断剑；
  - 失衡跪地：3 秒；
  - 第二阶段失衡时：五柄飞剑一起掉在地上。

### 5.4 弹射物

- **原版弹射物。** 原版和其他模组里继承原版 `Projectile` 的弹射物都算：箭、三叉戟、火球、药水、雪球、枪械模组的子弹、车万女仆的弹幕。它们碰到剑祟时走原版的 `deflection`：它空着时，手中剑一拨，一半弹回给射手，一半拨到旁边（同白梅）。
- **忙的时候背剑自己动**（补充：非人感）。离弹射物最近的一柄背剑从背上抽出来把它拍开，再插回去。每柄拍一下要等 1.5 秒才能再拍，五柄都在忙时还是打得中，多人齐射或者连发能压过去。第二阶段由绕身的飞剑来截。
- **不是实体的远程伤害**，比如瞬发的枪、其他模组的远程法术：看伤害来源，它正面对着时挡掉，冒火花（同白梅）。
- **爆炸**伤害减半。
- **一直在远处放冷箭的人**：背剑点射，同时滑过去。

### 5.5 反制 Logos 术式

Logos 的魔弹、光柱、游脉、领域都不是实体，原版的弹开碰不到它们。所以不改 Logos，用这几样：

- Logos 留给附属的拦截口 `Constructs.addWards`，附属的 `ManaGuard` 已经在用；
- 公开的蓄力和术式查询 `Charging.of`、`SpellRuntime.spellsNear`；
- 不够时加 `require=0` 的小 mixin。

| 反制 | 什么时候 | 做法 |
|---|---|---|
| 截剑 | 剑祟空着或者举剑守着，术式从正面 ±100° 来 | 魔弹、游脉的头、光柱在离它约 4 格处被一剑截断，炸成那个术式元素的火花。重的术式整条掐灭（`SpellInstance.stop`）：不触发术式里「结束时」的那一段，剩下的魔力全部散成游离魔力，不出提示。每截一下，剑上的光就暗一点，连着截多了它会被震得一顿，露出空档（补充） |
| 断咏 | 32 格内有人蓄力超过 1.5 秒，或者蓄了 150 点魔力 | 一柄背剑升起，拉出一道光线，0.6 秒后直射过去。第一阶段离得近（瞬步 8 格够得到）时，改成瞬步过去砍一刀。伤害按蓄进去的魔力算；蓄力被打断，魔力照 Logos 的规矩散成游离魔力。Logos 自己打断蓄力时会在动作栏出提示，这里用公开的几样东西自己拼一个不出提示的打断 |
| 镇剑 | 场地里有人放下领域、范围天气这类持续的术式 | 一柄背剑划过去钉在术式中心，剑上一圈光把术式吸进去，1 秒内散掉。剑钉在那里的时候，那一片放不了新的领域。打三下能把剑打出来（补充：交互）。同时最多钉一柄，新的镇剑先收回旧的；钉住的剑 12 秒后自己飞回；转阶段时全部收回 |
| 斩缠 | 剑祟弹反了带魔力缠绕的武器 | 缠绕当场断掉。之后 10 秒它对那种元素的抗性提高（虚空不受影响） |
| 逆光而上 | 有人用光柱一直照它 | 它把剑竖在光柱里，一路顶着光走过去，到跟前把光柱掐断，接一记重斩（能弹反） |
| 归剑吞魔 | 上面这些反制散出来的游离魔力 | 被它胸口的贯穿古剑往回吸。玩家也在吸，抢输了它的飞剑就更快（补充：每次被反制都有代价，而且看得见） |

另外还要加固：

- 不能被 Logos 的时停冻住；
- 不能被闪现挪走；
- 手里不能被塞东西；
- 冲击和推拉打折扣；
- 第三阶段只认真正的近战：不在术式里、也不是武器带出来的后续伤害（剑气、电磁炮这类）。

### 5.6 失衡

隐藏数值，同白梅：

| 来源 | 失衡 |
|---|---|
| 独立招式被弹反 | +30 |
| 连续招式其中一刀被弹反 | +18 |
| 受到伤害 | +伤害 × 0.35 |
| 2.5 秒没有新增 | 每秒 −8 |

到 100 时：

- 单膝跪地，剑插在地上撑住，持续 3 秒，这段时间受到的伤害 ×1.3；
- 站起来时快速一剑（照样闪光），然后后撤；
- 第二阶段失衡时，五柄飞剑一起掉下来插在地上，这 3 秒里用不了（补充）。

### 5.7 防卡位、离场、重置

- **玩家放的方块。** 战斗范围里（包括空洞）玩家放的方块都记下来，倒的水和岩浆也算。遇到下面几种情况，剑祟一剑把这些方块斩碎（附属的方块消散，不掉落）：
  - 被挡住 2 秒；
  - 够不到目标 3 秒；
  - 身边 3 格内有这类方块。

  每次转阶段时也全部斩碎（同白梅）。
- **实在卡住。** 散成碎片，在目标附近重新拼起来。用散架、倒放各 0.5 秒的短版（补充）。
- **离场。** 剑祟不出它的活动范围（第 2.1 节）。目标在范围外时它不追，用飞剑打；目标出了战斗范围，它回到铁链旁那一点。
- **重置。** 30 秒里战斗范围内没有活着的玩家时：剑祟回到铁链旁，剑插在地上静立，血慢慢回满，血条收起。有人进来就拔剑接着打，阶段不变。

## 6. 第一阶段：剑客

### 6.1 移动

- **不迈步**（补充：非人感，也省一套走路动作）。两腿保持待势，整个身子贴着地面滑过去，衣摆和袖子往后拖。
- **瞬步。** 一下子滑出 6–8 格，身后留两三道残影。
- **后撤。** 被围住时往后滑开 4 格。

### 6.3 掷剑与换剑

- **掷出。** 手中古剑旋转着飞出，飞出去的是一个飞剑实体，用 `jian_sui_sword` 的网格，从 `Weapon` 骨骼当时的位置接手，看不出换手。剑沿直线飞 16 格，或者撞到东西就停住，悬停 0.4 秒后划弧线飞回。去程和回程都伤人。
- **弹反去程**（补充）。剑被弹回来，打着旋插在剑祟脚边，它要弯腰去拔：空出 1.2 秒，失衡 +30。
- **落空。** 剑祟空着手站 1.5 秒，才从背上拔一柄断剑（`BackSword1`–`3` 中的一柄）握着，用断剑三刺。古剑飞回来时，它把断剑插回背上，接住古剑。
- **背上没有断剑时不掷剑。** 比如断剑被镇剑钉在地上，或者被打落了。
- **模型上怎么换。** 断剑的骨骼藏起来，`Weapon` 改画对应的断剑网格，断剑的握点在剑身外端。

## 10. 第三阶段：坠渊

### 10.1 布局

空洞里能踩的东西都是方块，材料和上面的场地一样，看上去就是刚塌下来的场地。

| 东西 | 脚站的高度（y） | 说明 |
|---|---|---|
| 剑祟所在的顶块 | −29 | 石台断下来的一块：闪长岩那层（r≤4.5）带玄铁心，外圈平滑石只剩几块，边缘断得不规则 |
| 垫脚的碎块 | −48 到 −30 | 地板碎块（深板岩瓷砖的环纹）和断柱的截面（石砖），里外两圈（离轴约 11、14.5 格）交错着往上盘 |
| 落脚台 | −42、−35 | 爬过三分之一、三分之二各一块，3×4 的地板碎块，角上立一盏魂灯。掉下去回到这个人到过的最高一块（维护者 2026-11-22 定） |
| 起点碎块 | −49 | 5×5 的地板碎块（缺两个角）。玩家落在这里 |
| 掉下去的判定 | 脚低于 −54 | 黑屏，回起点（第 10.4 节） |
| 空洞底 | −58 | 被下方那一层盖住，看不见 |

**路线：**

- 主路 26 跳（起点 + 25 块 + 顶块）：16 跳往上 1 格、8 跳平跳、2 跳高 2 格。格边到格边，往上跳隔 1–2 格，平跳隔 1–3 格。
- 两处故意高了 2 格（第 11、21 跳），要借插住的巨剑的剑格才上得去（第 10.3 节）。这两处各有一条绕路，不靠剑也能上去（补充）：从这一跳之前的某块出发，走外圈的四块碎块（每跳最多高 1 格），接回这一跳之后的某块，比主路多一两跳。
- 里外交错是为了少占角度：整条路转了一圈多一点（427°），最上面几块在最下面几块正上方十几格。生成脚本逐块检查：头顶 4 格、跳的路上不碰头；每块离别的碎块至少隔 1.5 格（上下差 7 格以上的不算）；剑祟沿顶块边缘走到合适的地方（偏开不超过 60°）出手时，看得到每一块。
- 种子固定（`SEED`），排不出来就换下一个种子，所以每次导出都一样。

**碎块的样子：**

- **顶面**：平的，就是一块地板，踩着稳，上面不加斜的装饰。
- **底面和侧面**：挂着倒锥形的碎石和断掉的地基，材料用深板岩、圆石、凝灰岩（模板不许用沙砾和沙子）。从下往上看，满眼都是悬着的碎块。
- **斜着的样子**：放在人站不到的底面、侧面，还有只看的碎块上（第 13 节）。
- **不晃动，也不上下浮动**：一来脚下要稳，二来前景跟着背景一起动会削弱下坠感。

**范围**：主路在半径 16.6 以内，两条绕路在外圈（到 21.5），只看的碎块在 23–28.5，外面那一层的几层壳在 29–35，真洞壁在 36 以外，永远看不到。

### 10.2 下坠感

场景本身一动不动，四周一直往上流，人就会觉得自己在往下掉。这是游戏里做下坠的常规做法。维护者给的参考是《师父》大厦一章的 Boss 金凤：第二阶段地板裂开，带着钟的那块平台一路下坠。

「外面」这一层原稿列了两种做法，维护者 2026-11-22 选了做法 A，并说「可以试试信标光柱的几何改成圆形，多叠几层，放上一些移动的纹理」。现在的做法（`client/jiansui/FallStageRenderer`）：

- 场景实体 `FallStage` 放在空洞竖轴上，不存档；客户端围着它画。
- 三层圆筒，像信标光柱那样画（原版的信标光柱材质，全亮、法线朝上），改成圆形：最外 r 34.8 是不透明的岩壁（层理、斜裂缝、零星淡青白的矿脉），里面 r 32.2、29.4 是两层半透明的雾（竖着拉长的软条纹）。贴图按「累计往下掉了多远」往上滚，三层同一个速度；越往下越暗（光从上面来）。
- 顶：一片发亮的淡色雾，中间最亮；底：一片黑，中间透出一点淡青白的冷光。壳和顶、底之间各有一圈渐变的雾，把接缝藏起来。
- 贴图由 `tools/jian_sui_fall_art.py` 画，都能无缝平铺。

原稿的两种做法留作对照：

| 做法 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| A. 场景实体画一层壳（先试这个） | 场景实体在舞台四周画一圈不透明的圆筒，再加顶、底两片，半径 30，在真洞壁里面。每一帧逐个顶点算出视线和半径约 50 的虚拟圆筒的交点，拿交点去取纹理。这样壳虽然只有 30 格远，纹理看起来却在 50 格远的地方往上滚 | 和普通实体一起画，玩家、手、粒子、术式都照常挡在它前面，不会被盖掉 | 光影包会给它打光、加雾，样子随光影包变；发光的部分按 AGENTS.md 第 36 条写全顶点，走 `ShaderPackOverlay.item` |

### 10.3 巨剑贯落

（维护者给的设计，括号里的数值是补充的）

- **出手位置**。每次起手前，剑祟沿顶块边缘走到离目标最近的那一侧，抬手指向这个人。多人时轮流指，偏向爬得最高的人。巨剑在顶块边缘外成形，不和顶块碰撞。
- **蓄光**。从剑祟手边到这个人脚下连出一道细光，光点沿这条线往里聚，线越来越粗、越来越亮，共 1.4 秒。线在起手开始时就定死，之后走开就躲掉了。
- **射出**。1.4 秒时，一柄巨剑一闪成形：手中古剑放大四倍，约七格长，淡青白的光凝成，半透明。它沿着这条线射下来，0.25 秒到底。
- **打中**。离线 0.8 格以内、或者离线尽头 1.2 格以内算打中：伤害 10，顺着剑的方向往下、往外击退约 6 格，站在碎块边上的会被打下去。举盾能挡掉伤害，但挡不住击退，也不破盾。
- **节奏**。同一个人两次被瞄准至少隔 4 秒；刚被送回起点的人，2 秒内不会被瞄准。爬过三分之一后，有时两柄先后射来，隔 0.5 秒；最后一段是三柄成扇形。

  - 没扎进碎块的（比如人正跳在半空），剑直接穿过去掉进下面，不留下。
  - 离顶块 7 格以内的不留剑格，不能借它直接上顶块。
- **弹反**（补充）。拿带弹刀的武器，在剑到的那一刻弹反，巨剑会被弹回去打在剑祟身上，它晃一下，5 秒内不射剑。

## 11. 终结：撬出贯穿古剑

**维护者 2026-11-22 定的做法：** 做成和处决特写同款的黑白处决，新做一种「飞身刺」：玩家的剪影和剑祟的剪影，玩家拿着剑飞身刺向剑祟。趁画面黑白的这一下换场景，回到上面的雾底场地，再从「剑已经刺进去」（下表的 0.3 秒）接着演后面的。所以：

- 打中以后：顿帧 0.15 秒，四周往上流的东西一下子停住（补充：原来的「终结时下坠慢慢停住」挪到这里）；
- 黑白处决约 1 秒：白底黑剪影，玩家从几格外飞身刺进剑祟胸口。全屏黑白的这一段里，所有在空洞里的人被送回上面场地各自记下的位置，剑祟摆到插剑的地方，空洞里的场景删掉；
- 退回彩色时已经在上面了，从下表 0.3 秒那一行接着演；最后不用黑屏，镜头回到玩家、遮幅收起就结束；
- 崩飞出去的贯穿古剑旋转着飞进雾里，再落下来插在插剑的地方，就是留下的遗剑（补充，第 12 节）。

**做成的样子（2026-11-22）。** 时刻按刻、从打中那一下算，常量都在 `JianSuiFight`（`FIN_*`、`PRY_*`、`BURST_AFTER` 这些）；黑白那一段的画面见 EXECUTION_SHOTS 的「飞身刺」，它的时刻（`ExecutionTimeline.THRUST_*`）从第 1 刻算：

|---|---|
| 0 | 近战打中：进终结；四周往上流的东西一下子停住；空洞里的人不受伤，护到最晚收尾之后；一声击中。这一下还在玩家的出招结算里，别的都排到下一刻 |
| 1 | 空洞里的人都看黑白的「飞身刺」，打中的人是出手的那个；附近别的人只看到两个人的姿势。同一刻暂停打中的人的战斗骨架（`LongswordCombat.pause`），并告诉附近的客户端谁在撬、撬哪一只（`JianSuiPry.Start`）。特写开头 3 刻是彩色的顿帧（0.15 秒） |

- **按键和撬剑的节奏。** 另写了一个用可交互处决零件的终结，没有用 `InteractiveExecutions`（它会定住剑祟、打中的人走了就中途结束，也没有「最多三下」和「自己撬」）。服务端 `JianSuiFight` 按刻走，是唯一说了算的一方：`pryPress` 收客户端发来的 `JianSuiPry`，只认打中的人、只认窗口里、最多三下，排队等轮到；每刻最多撬一下，两下至少隔 8 刻；轮到第 i 下的最晚时刻还没按就自己撬。按了只会让它更早，不会卡住。客户端 `JianSuiFinisherClient`：从黑白开始到镜头回来，打中的人的攻击键（鼠标或键盘，按它绑定的那个）都吞掉，不交给原版；窗口里按一下就发给服务端，本机先响一声；最多三下，两下隔 8 刻。屏幕上没有任何提示。
- **服务端一定会走完。** 终结按时刻走，不看打中的人：他死了、下线了、离开了，照样自己撬完、崩出、收尾。打中的人下线、死亡时，战斗骨架的暂停就清掉，再上线时是平常的样子。命令重置、跳过终结时，也恢复他的战斗骨架，镜头马上往回走。读档时处在终结，照第 14 节直接收尾。
- **玩家的动作。** 撬剑的姿势照处决特写摆人形的四肢：`JianSuiFinisherClient` 在玩家的渲染状态修改器里写 `ExecutionClient.BODY`，四肢是直接替换的 `Pose`，没加新的 Mixin。起点是 `ExecutionClient.impaled`，就是「飞身刺」刺中后定住的样子，接过来不跳。朝向按剑祟现在的朝向算，换场景时它被转成了朝外。手里的东西照原版画，任何模组的、空手都行。终结期间打中的人的战斗骨架暂停，所以打刀、流火、黑钢长剑这些也照原版画。剑祟的反应是 `JianSuiRenderer` 按每一下的时刻在骨骼上加的：两臂沿「被撬」动作本身的方向多转两成；贯穿古剑沿剑身往外推；面具朝前最大那一块上画深色细裂纹，跟着头走。
- **规则上的例外。** 过场里不管拿什么都拦攻击键，是 COMBAT_SKELETON 第 1 节第 7 条的例外，维护者 2026-11-22 批准（第 20 节第 14 条），只在这段过场里。
- **没做的补充。** 空手时一把攥住头顶贯穿古剑的剑柄没做，空手也是双手往胸口里按。

| 1–3.5 秒 | 一下一下推近 | 撬三下（补充：交互）。玩家每按一下攻击键：武器往下一压，贯穿古剑往上顶出一截，面具裂开一道，剑祟两只手抽搐着抓向玩家的武器，同时顿帧、轻抖、一声金属摩擦。不按也会自己慢慢撬，不会卡住 |
| 3.5 秒 | 仰拍 | 最后一下：贯穿古剑从头顶崩飞出去，旋转着往上飞，拖着一道淡青白的光，飞进上方的亮雾里看不见了 |
| 4 秒 | 退远一点 | 双眼熄灭，剑祟散架（用去掉贯穿古剑的那一版），碎块散在顶块上；玩家被震退一步 |
| 5–6 秒 | 静止 | 风声停下（往上流的东西在打中的那一下就已经停住，场景也在黑白那一下收掉了） |
| 6 秒 | 慢慢黑下去 | |

原稿里做法上要注意的几点（都按上面「做成的样子」做了）：

- **点击和镜头。** 照可交互处决 `InteractiveExecutions` 的做法：锁镜头、攻击键变成撬、服务端按节拍结算、中途结束的条件。但它现在的画面（把目标抛起、黑白平涂、拍下）不合适。所以要么给它加一种「撬」的样式，要么另写一个用同样零件的终结，由维护者定（第 20 节）。
- **服务端一定会走完。** 撬的那个人死了、下线了，或者离开了，服务端照样把剩下的撬完、散架、黑屏、送人回去，不会卡在一半。
- **玩家的动作。** 照处决特写摆人形模型四肢的做法，模型和手里的东西照原版画，所以其他模组的武器、空手都画得出来。但手里拿的如果是本附属的战斗武器（打刀、流火、黑钢长剑这些），平时由战斗骨架接管：原版手臂藏起来，原版持物层也不画。所以终结期间，要对这个玩家暂停战斗骨架。测试时打刀、流火、黑钢长剑、空手、原版剑都要试一遍。
- **规则上的例外。** 过场里不管拿什么都拦攻击键，算 COMBAT_SKELETON 第 1 节第 7 条的例外（只在这几秒的过场里），要维护者批准（2026-11-22 已批准）。

## 12. 回到场地与遗剑

- **黑白处决的那一下里**：第三阶段的所有玩家被送回雾底场地，各回各自记下的位置；空洞里的画面删掉。剑祟到撬完、散架以后才用 `discard` 移除。
- **亮起来以后**：场地完好，裂缝已经暗了。贯穿古剑插在剑祟当初插剑的地方，也就是手中古剑断在里面的位置，剑身上一点淡青白的光慢慢暗下去。补充：落剑的地方一圈地砖换成裂纹瓷砖，留个疤。
- **贯穿古剑是方块**：带方块实体渲染，照曦誓的石中剑做，打不坏，拿不走。以后做奖励物品时改成能拔起来，石中剑现成就有「握住往上拔」的做法。
- **一处场地只能打一次**：以后再来，只看得到那柄剑。维护者 2026-11-22：正常不能重打，可以用指令重置（同白梅）。

放遗剑、留疤、第 10.3 节的剑格，和战斗开始时重放空洞一样，是战斗中在太玄的地方用 Java 写方块（维护者批准了重放空洞；遗剑、剑格、留疤是「可以都加」的补充）。

## 13. 第三阶段的道具做成什么

维护者问：这些模型当实体还是当方块？建议按用途分开：

| 东西 | 做成 | 为什么 |
|---|---|---|
| 能踩的：起点碎块、垫脚石、剑祟所在的顶块 | **方块**。写在空洞的模板里，材料和场地一样 | 碰撞可靠：服务端和客户端算得一样，巨剑击退、掉下去这些规矩自然成立。光影包下和普通地形一样画。整块只建一次网格，什么都不用同步。做成实体不行：原版一个实体只有一个不会转的轴对齐碰撞盒，拼不出断口和不规则的边；而且实体碰撞在客户端靠预测，被巨剑击退、贴边站的时候不如方块稳 |
| 只看的：断柱、下坠的魂灯、斜着的地板块、断链；能踩的碎块底面和侧面那些斜着的装饰 | **客户端画的碎块，挂在一个实体上**。第三阶段开始时生成一个不存档的场景实体，客户端按种子画出所有碎块，各自慢慢翻转；断链按一串链环摆，往上弓、慢慢晃 | 碎块用场地里那几种方块的原版模型拼成：石砖、裂纹石砖、磨制安山岩、深板岩瓷砖、魂灯、玄铁。拼法和上面的场地是同一套，看起来一模一样，**不用新贴图**。整场只发一个包，结束时删掉一个实体就干净了。场景实体丢了（比如被爆裂魔法清掉）就重新生成 |
| 往上飞的碎石和尘土 | 跟着「外面」那一层的做法：做法 A 由场景实体画，做法 B 走 `PostVfx` | 见第 10.2 节 |
| 留在场地上的贯穿古剑 | **方块**，带方块实体渲染 | 要一直留着，以后还要能拔 |

只看的碎块为什么不做方块：方块模型最多伸出本格一格（一个模型不超过 3×3×3 格），转不了（一动就得重建整片区块的网格），大的模型跨区块时会忽隐忽现，光照还有接缝。

为什么不是每块一个实体：几十个实体每个都要同步；原版的展示实体还会存进存档，服务器崩了就会留下没人收拾的碎块。

魂灯画出来不会照亮周围，它旁边写进模板一个看不见的光源方块；火苗用全亮画，再加泛光。

## 14. 多人、存档、重连

- **锁定目标**：同白梅，偏向当前目标，被打时有机会换人。第三阶段的巨剑偏向爬得最高的人，轮流打。
- **一起下去**：转进第三阶段时，战斗范围里的人一起下去。之后才来的人，踩到石台上发光的裂缝就会被吸下去。用的是和裂地一样的 `ScreenEffects.cover`：至少 0.5 秒白下去，全白时传送，再淡出；开了「隐藏闪电的闪烁」时拉得更长。
- **没人了**：第三阶段里 30 秒内空洞里没有活着的玩家时，删掉第三阶段的画面，剑祟回到场地里，摆成剑插在地上的样子（裂地第 1.5 秒），裂缝暗着。有人靠近时，从裂地第 2 秒开始重放，再进第三阶段。
- **死了**：在第三阶段里死了，照常在出生点复活。回到场地踩裂缝，可以再下去。

战斗记录 `jian_sui_arenas` 按结构起点存这些东西：

- 阶段：未开打、登场、第一阶段、离体、第二阶段、裂地、坠渊、终结、已打败、没有剑祟；
- 根部件的位置和旋转；
- 剑祟和残骸的 UUID；
- 每个玩家回去的位置；
- 临时放的方块（剑格碰撞方块等）。

读档、重连时这样处理：

| 情况 | 处理 |
|---|---|
| 读档时处在登场、离体、裂地 | 过场不重放，直接跳到这段过场结束时的样子 |
| 读档时处在坠渊 | 退回「没人了」的样子：剑祟在场地里，剑插在地上，裂缝暗着，等人靠近再重放 |
| 读档时处在终结 | 直接收尾：放遗剑，记成已打败，删掉剑祟和场景 |
| 读档时有临时方块 | 一律清掉 |
| 有人在空洞里上线，第三阶段还在进行 | 送回起点碎块，重新发给他第三阶段的画面状态（场景、外面那一层、雾、风声） |
| 有人在空洞里上线，第三阶段已经不在进行 | 送回记下的位置 |

- **新动作都用脚本做**（维护者 2026-11-22 定），包括原稿里标「手做」的几个（拔断剑、被弹反、失衡跪地、反手斩、被撬）。手臂的风格尽量贴近 PR #280 的三招。
- **骨骼要写全。** `collapse` 只写了 56 根骨骼，播的时候底下还在跑待机。散架、倒放、残骸都要把 152 根骨骼写全，不动的写静止值。它们也不能当成死亡动画播：真进了死亡状态，原版 20 刻后就把生物移除了。
- **衔接要做进动作里。** GeckoLib 对 NPC 的招式切换只有固定的 1 刻过渡，招式文件里的 `blend_in` 不起作用，所以招与招之间的衔接要在动作本身里做好。
- **审计加一项**：在 `tools/audit_jian_sui.py` 里检查每个旋转通道的末帧和 `idle` 首帧，差不超过 180°。
