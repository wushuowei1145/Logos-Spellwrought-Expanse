# NPC 人口与繁殖

适用于附属模组在聚落里生活的 NPC：幼年与成年、成长、聚落人口怎么增加、伴侣与生育、外观遗传。外观本身见 [NPC 随机外观方案](NPC_APPEARANCE.md)。

本文是设计方案，**尚未实现**。原版机制按 26.1.2 的 `AgeableMob`、`Villager`、`Animal` 核对过（见第 1 节）。

## 1. 年龄：直接沿用原版 `AgeableMob`

NPC 继承 `AgeableMob`，年龄规则全部照原版，不另造一套：

| 原版机制 | 规则（26.1.2） |
|---|---|
| 年龄 `age` | 负数为幼年，0 为可繁殖的成年，正数为成年但在繁殖冷却中。存档在 NBT 的 `Age` |
| 成长 | 幼年且没有锁龄时每刻 +1；成年且为正数时每刻 −1（冷却倒数） |
| 幼年标记 | `age < 0` 时为幼年，同步给客户端；跨过 0 时触发 `ageBoundaryReached()` |
| 出生年龄 | `getBabyStartAge()` 默认 −24000（20 分钟长大） |
| 锁龄 | 26.1 的金蒲公英可以锁住幼年个体不长大（`isAgeLocked()`） |
| 能否繁殖 | 村民的 `canBreed()` 要求 `getAge() == 0`；幼年和冷却中都不行 |

- **独立幼年模型**：26.1 原版幼年生物已有独立模型（`AdultAndBabyModelPair`），NPC 照同一思路，按幼年标记切换成年 / 幼年模型，不把成年模型缩小。
- **碰撞箱**：26.1 的 `getScale()` 只来自 `SCALE` 属性，不再乘幼年系数；幼年尺寸由 `getDefaultDimensions` 决定。照村民的做法，重写它返回单独的幼年尺寸，按幼年模型实际大小设置。
- **身高系数**照常通过 `SCALE` 属性叠加，幼年、成年都生效。
- **长者**不是原版年龄，是外观记录里的成年外观段（青年 / 成年 / 长者），和原版年龄无关。

## 2. 人口增长方式按种族配置

| 方式 | 适用种族 | 说明 |
|---|---|---|
| 树生 | 森林精灵 | 聚落人口没到上限、并满足条件时，从巨树核心诞生（第 3 节） |
| 伴侣生育 | 灵猫、神狐、人类 | 第 4 节 |
| 迁入 | 所有种族都可以叠加 | 旅人定居，直接是成年，不需要幼年模型 |
| 不增长 | 稀有种族、重要 NPC | 只在结构生成时出现 |

- 代码里由「聚落人口管理」统一判断什么时候可以新增一个 NPC（人口上限、住所、资源），再交给种族声明的方式执行。
- 种族在数据里声明用哪几种方式，以及各自的权重和条件。
- 新生个体以 `getBabyStartAge()` 的年龄出生，用中性的幼年模型，到 0 时长大。

## 3. 树生（森林精灵）

- **地点**：世界树或带树屋的巨木的树心。
- **条件**（暂定，仿照原版村民繁殖要床和食物）：
  - 聚落人口没到上限；
  - 有空置的树屋或床位；
  - 附近叶灯、苔地等「森林健康度」达标，巨木没有被砍伐破坏。
- **过程**：树心结出精灵芽，经过一段时间后诞生一个幼年精灵。性别和外观颜色按种族权重直接抽取，没有父母可继承。
- 玩家砍伐巨木会降低森林健康度，影响人口增长。

## 4. 伴侣与生育（灵猫、神狐、人类等）

原版任意两个村民都能繁殖，日漫风格的外观一眼能看出男女，会出现很尴尬的场面。所以生育只发生在**固定伴侣**之间。

### 4.1 结成伴侣

- 同一聚落里、都是成年（`!isBaby()`）、都没有伴侣的两个 NPC，相处一段时间后结成伴侣。
- 双方互相记住对方的 UUID，存档在各自的 NBT 里。
- 伴侣关系本身是否只限一男一女，**待定**；只影响谁和谁能结成伴侣、一起住，不影响生育规则。

### 4.2 生育

- **生育只发生在一男一女的伴侣之间**，此外照原版：
  - 双方 `getAge() == 0`（都不在幼年、都不在冷却）；
  - 资源条件仿照村民：食物足够、有空床或空屋。
- 生育后双方进入冷却（原版村民为 `setAge(6000)`），孩子以 `getBabyStartAge()` 出生。
- **爱心粒子只出现在伴侣之间**。
- 跨种族伴侣允许，但**不做混血种族**：孩子随父母中的一方（各 50%），颜色从两边继承（第 5 节）。

### 4.3 伴侣关系的「休眠」

伴侣记录只在一方死亡、或下面的长期休眠时清除，其他情况一律保留。

- 任一方为幼年（`isBaby()`，例如被衰退符文变回幼年）时，伴侣关系**休眠**：
  - 记录保留，不清除；
  - 不显示任何伴侣行为：不冒爱心、不同住同睡、对话不以伴侣相称；
  - 不能生育（原版 `getAge() == 0` 的条件已经挡住）。
- 双方都恢复成年后自动恢复，不需要重新结成伴侣。
- 休眠是根据当前年龄算出来的，不额外存状态。
- **长期休眠**：如果一方被金蒲公英锁龄，可能永远不会长大。建议休眠超过一定天数（暂定 3 个游戏日），或对方被锁龄时，另一方可以解除伴侣关系。

## 5. 外观遗传

孩子的外观记录按项继承：

| 项目 | 规则 |
|---|---|
| 发色、瞳色、肤色 | 约 45% 像母亲、45% 像父亲、10% 突变（从种族色阶里重新抽） |
| 身高系数 | 父母平均值加一点随机 |
| 种族、耳尾型 | 随所属种族的一方 |
| 性别 | 各 50%（比例可按种族调） |
| 五官图块 | 从父母两边各项中选，少量突变 |
| 发型、服装 | 不遗传，按年龄和职业另外选 |

兄弟姐妹会看起来像一家人。外观记录存的是解析结果，父母的记录可以直接拿来混合。

## 6. 成长

- 幼年用中性幼年模型、幼年零件组；对话用名字称呼，不用他 / 她。
- 第一次长大时（原版年龄跨过 0）：按性别切换成年身体，生成成年零件组（发型、服装、体型、头饰）。颜色、五官、耳尾不变，长大后认得出是同一个人。
- 以后再变回幼年、再长大，都恢复同一套成年零件组（见外观方案第 6 节）。

## 7. 与衰退符文的交互

Logos 的衰退符文对 `AgeableMob` 执行 `setAge(getAge() - 6000)`（`dev.logos.lang.Runes` 中的 `decay`）。按原版机制分析：

| 被作用的 NPC | 结果 | 原版能否处理 |
|---|---|---|
| 成年、`age == 0` | 变成 −6000，成为幼年，约 5 分钟后长回成年 | 能：幼年不能繁殖；伴侣关系按第 4.3 节休眠，记录保留 |
| 成年、冷却中（`age > 0`） | 冷却被扣减，**可能直接变成 0 或仍为正数，没有变回幼年** | **不能**，见下 |
| 幼年 | 幼年期再延长 6000 刻 | 能 |
| 被锁龄的幼年 | 年龄变小但仍锁住，不会长大 | 能，但伴侣可能长期休眠（第 4.3 节） |

**冷却中的问题**：刚生育完的伴侣 `age` 约为 6000，衰退一次正好归零，冷却被清空、可以马上再生，变成一个廉价的催生手段（每个对象 2 魔力）；这也和符文说明「成年变回幼年」不符。原版动物同样有这个问题。

**建议修改符文**（主模组改动，另开 PR）：先把正数年龄视为 0，再扣减，即 `setAge(Math.min(getAge(), 0) - 6000)`。这样被作用的成年个体一定变回幼年，冷却随之作废，长回成年后从 `age == 0` 开始，规则与原版一致。

除这一处外，「伴侣记录保留、幼年期间不能繁殖、长大后恢复」完全可以靠原版年龄规则加第 4.3 节的休眠判断实现，不需要额外状态。

## 8. 准备顺序

1. 外观记录带上性别、成年外观段、幼年 / 成年两组零件（外观方案第 6 节）。
2. NPC 基类继承 `AgeableMob`，接好幼年模型切换和幼年碰撞箱。
3. 聚落人口管理加「按种族配置的增长方式」接口，第一个只实现树生。
4. 伴侣、生育、遗传写好设计，等第一个需要两两繁殖的种族时再实现。
5. 衰退符文的冷却问题在主模组另开 PR 修复。
